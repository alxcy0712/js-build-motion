# 布局与成片质量

适用于 Grok Bot 团队与 Codex 等本地 Agent 的竖屏制作、改片与画面复盘。规划时与[导演计划](direction.md)一起读取，实现时配合[绘制](drawing.md)，审片时配合[成片质量](layout-and-quality.md)。让实景充分使用竖屏空间、主体有足够尺度，留白承担明确的表达用途；本片已确认的风格、事实、音源与审批继续沿用。素材访问、配音和执行环境按根 AGENTS.md 的角色分工处理。

## 先区分位置、尺度和版式

先从当前交付记录找到实际 MP4，登记哈希、画幅、帧率与取样时间。已有影片的衍生剪辑按当前交付入口读取；源码、历史帧与当前编码分别标明。检查编码宽高、像素宽高比和旋转信息，再在原比例完整画幅内观察；播放器窗口与编码画面分别定位。

| 现象 | 核对依据 | 对应操作 |
|---|---|---|
| 主体持续偏向一角 | 主体与关系图的实际外框、预期焦点、素材自身空边、相机变换；同时看高亮与大字的视觉重量 | 修正主体锚点、素材裁框或相机焦点，重排相关标签 |
| 已居中，画面仍显小 | 主体宽高占比、照片窗口占比、四周空带及其用途 | 放大主体或更换取景，按镜头重新安排图文关系 |
| 连续多镜像同一页 | 全片联系表中的标题带、中央窗口、来源行与景别分布 | 按内容改为环境全貌、对象近景、局部解释或结果停留，保留同一识别体系 |

平移改变位置，缩放改变尺度，重构图改变信息的空间关系。对多种镜头分别选择操作，并复核字幕、来源和相邻切点。

## 分开三层坐标

| 图层 | 设计范围 | 检查重点 |
|---|---|---|
| 场景／环境 | 以整个编码画布铺设实景、环境或有意义的图形空间；推拉过程也覆盖画幅 | 实景的边缘连续、缩放后的露底、源素材内嵌黑边 |
| 主体／关系 | 根据本镜意义选择全貌或局部，以完整画布的预期焦点组织尺度 | 对象、必要地标、动作空间、关系完整性与光学重心 |
| 文字／字幕／来源 | 在平台界面避让区内安排必要信息，字幕保留自己的稳定位置 | 字形边缘、对比、读时，平台按钮和字幕对关键证据的遮挡 |

`SAFE_AREA` 与 `VERTICAL_SHORT_LAYOUT` 的权威值在固定运行时的 `src/themes/shared.ts`，用于必要信息的避让与布局起点。左右、上下边距有意不同，安全矩形中心会偏离画布中心。全画幅背景按画布铺设，主体按镜头焦点定位，必要标签按安全区避让。沿用既有 token 与引擎契约，布局调整在本片 `src/` 完成。

在同一逻辑画幅内计算主体锚点，再统一映射到编码或预览尺寸。以 1080×1920 为例，画布中心为 (540, 960)；实际焦点可因视线、动作或证据避让而偏移，记录用途。把照片窗口、对象外框、标题与字幕分别画出辅助框，核对其屏幕位置。单个字形的越界检查覆盖裁切风险；全片联系表与当前编码取样覆盖构图判断。

主体、连接线与世界标签共用相机变换；屏幕字幕、来源与固定信息各自排版。`save/restore` 分离图层变换。源图自带留白或透明边时，依据可见对象外框定位；全局平移只用于已证实的共同坐标错误。

## 按镜头决定占幅

- **实景与环境镜头**：从全画幅取景起步，把必要短标题或标注叠在场景上，通过局部底板或渐变维持对比。检查人物、招牌和当前证据的裁切；横图承担完整关系或证据时保留其完整视图，再安排背景与解释空间。
- **主体与机制图解**：按需要看清的关系放大主体，允许环境、路径与次要轮廓延伸至边缘。长过程先建立全貌，再推近当前动作，最后回到完整结果。固定比较尺度、单位和对象身份；标签及关键连接点保持可读。
- **截图、对照与数据**：完整性优先，适合 `contain` 或局部放大加位置线索。比较对象保持共同尺度；镜头空间由本次证据决定。
- **提问、停顿与结论**：纯色背景和大面积留白可用于集中注意。明确主词／对象、尺度和停留用途，与前后镜头形成强弱变化。

图片的 `cover` 只保证覆盖传入的目标矩形。需要全画幅时，目标框使用整个画布；裁切前检查源图中的关键对象，并按裁后有效像素核对原尺寸清晰度。裁后细节不足时缩小取景放大幅度，或按既有素材授权补充更合适的原件。`contain` 用于完整展示；保留源比例。需要时按[绘制入口](drawing.md)复制 `image-fit` 组件，使用现有 `fitImage`。相机推拉与素材适配各指定一个控制位置，复核最终叠加尺度。

将页眉、标题、资料窗口和来源按其信息用途出现。用[镜头编排](direction.md)比较相邻镜头：实景提供空间，近景给细节，图解解释关系，简洁镜头承接停顿。`minimal` 可以采用铺满的实景与大尺度主体，动作强度继续遵循已选主题。

## 以同内容对照验证

已有片反馈“偏移／未铺满”时，从已定位问题中选有代表性的实景、图解与留白镜头；新片把这项比较纳入既有粗剪。保留相同内容、时间点和观看尺寸，对照位置调整与尺度／构图调整的结果。试排与正式采用分别记录，沿用本片的视觉审批约定。

在现有 `events.md`／`review.md` 中记录：时间码、镜头任务、主体外框、焦点、留白用途、修正与编码复核。外框先按照片窗口或可见主体定义口径，再计算 `宽/W`、`高/H` 与中心 `(x+w/2, y+h/2)`；背景覆盖、窗口占幅和主体占幅分别记录。几何中心辅助定位，视觉重心同时看对比、亮度、文字和运动。全画幅暗场与单色图解按其内容判断，像素亮度统计仅作定位线索。

占幅的具体数值由题材、素材裁切、平台遮挡和阅读任务决定。跨镜比较能暴露反复偏移、相同小窗口及无明确用途的空带；检查重点是主对象与证据能否被看清、镜头空间是否服务当前内容。

验收复用三种已有观察：

1. 全片联系表：保留完整 9:16 边界和时间码，检查主体位置、上下空带与连续镜头的尺度变化。
2. 360px 宽预览与平台界面遮挡示意：对照干净画面核对主体、关键地标、标签及字幕。示意区标明依据，实际发布界面可用时按其复核。
3. 运动极值、切点两侧连续帧与正常速度片段：检查推近后的裁切、移动时的露底、焦点跳动和阅读窗口。分别记录实际完成范围。

退出条件是对应问题有新编码或试排证据，关键事实和标签完整，手机尺度可读，留白与景别有明确作用。单次构图对照支持该条件下的改进；完整叙事、声音与受众理解继续按各自观察范围评价。维护证据、参考身份和具体项目数据按核心维护（由宿主按仓库核心维护规范执行）保存在本地项目。

## 成片质量

以用户要求、受众、目标平台与 brief.acceptance 为验收依据。技术检查和创作检查各自保留结果：文件完整、配音存在和文字可读支持技术交付；叙事推进、构图变化、运动质感与节奏支持创作完成。创作检查仍有缺口时，交付注明待审范围，制作状态采用“已编码，创作待审”。

## 当前版本与观察范围

按[音视频流程](workflow.md)运行 artifact，在 evidence/review.md 引用当前 MP4 的 SHA-256、runId 与固定运行时。抽帧、短片、解码、声轨和观看结论分别注明版本、时间码、方法和范围；交付前复核身份绑定。

机器检查、静帧、连续动态、正常速度观看、主观试听、用户验收各自记录。播放器 ended、完整解码和音频信号提供对应机器事实；速度、节奏、声音与理解依据实际视听观察。用户的观感反馈进入问题表，与原有机器结果共同保留。

文件改变后当前审片回到 pending，历史记录注明适用版本。仅封装变化时，核对解码画面、音频内容和时间轴的一致性，再保存新旧哈希映射并沿用对应观察；原有 pending 项继续保留。画面或时序变化时复核改动与相邻切点；变化范围未知时复核全片。

## 创作检查与预演退出条件

按[导演计划](direction.md)先审完整动态粗剪，再审正式素材的重点样片。以下各项以可定位观察填写 pass、revise 或 pending；分数可以辅助比较，同一轮的自评分需附依据。

创作结论回到本片约定的[首要体验与取舍](motion.md#创作主线)，分别记录理解、识别或情绪的观察依据。模型评审、用户偏好与实际受众反馈注明各自来源；采用对照实验时引用对应版本、改变因素和支持范围。

| 维度 | 在当前编码中检查什么 |
|---|---|
| 开头与主线 | 开场的具体问题、动作或结果建立兴趣；观众能追踪同一任务、对象或关系 |
| 状态推进 | 每段有起始、动作与结果；入场后的中后段继续推进，停留支持阅读或情绪 |
| 构图与景别 | 并排比较全部镜头的主体占比、关系和留白；近景、全貌或稳定图解按内容形成节奏 |
| 动画质感 | 触发、加速、接触、次级响应与落定有清楚分工；连续改目标时位置和速度接续 |
| 相机与转场 | 起止构图之间有可见的发现；焦点稳定、分层有作用、相邻镜头接力明确 |
| 声音与阅读 | 实测语义词、动作和音效对齐；音乐强弱与停顿有层次；360px 宽下主体和字幕可读 |
| 身份与事实 | 品牌地标、人物、结构、方向、单位和比例稳定；示意与真实证据口径清楚 |
| 个人包装 | 按[固定识别与组件验收](style-and-identity.md#审片验收)核对实际选用（含片尾卡是否经用户确认、是否与片尾口播同步，未采用时有无残留收尾口播）：字体层级、黄色标记、容器与同类进退场一致，字幕／人物条／来源互相避让，最拥挤镜头和代表性变体有当前编码证据 |
| 动效意义与文字权重 | 按[共用动效标准](motion.md)回答主题、镜头意义、动作／运镜理由；对象和关系支持主张，大字承担明确的提问或结论 |
| 色彩与强弱 | 品牌黄和变量颜色职责稳定；换色有状态依据，正文对比、手机可读性、亮暗闪烁与强动效后的阅读停留逐段检查 |
| 现实规则 | 写实／示意／抽象口径明确；受力、接触、尺度、透视与播放方向符合本镜模型，教学简化有说明 |
| 外部资料与复用 | 事实来源、权利范围、必要署名和目标平台规则分别核对；同源再次使用记录可见的新分析，必要标识或比较基准注明持续用途 |

承担解释的镜头在表达效果待判断时，可暂时遮住标题与装饰大字，记录还能看清的对象、变化和结果；文字推导及引文保留其必要文本。结果依赖口号时补对象、动作或证据。复杂转场的理解收益按[小对照](motion.md#设计判断与有条件的方法)在需要时比较。上述检查辅助分镜修正，完整声画观看继续验证主题理解与惊喜出现的位置。

三种取样各解决一类问题：全片联系表看构图分布；动作与切点的连续帧条看跳变、重影、遮挡和中间态；正常速度播放看速度、停留和注意力。联系表分页覆盖全片，记录每页时间范围。快速动作按实际帧率取连续帧；编码后复核真实字体与边缘清晰度。主体细节按[精确几何](drawing.md)检查，字幕按[语义分镜](captions.md)检查。

## 渲染期布局 QA

普通 `qa` 同时运行结构检查与逐帧绘制追踪，`qa --layout` 可独立复核；`diagnose` 在指定连续窗口运行同一几何／动效检查。检查依据时间轴、实际字形路径与最终合成变换，硬性违例返回非零退出码，报告保存在 `out/layout-qa/report.json` 或诊断报告中。

| 量化门禁 | 判定 |
|---|---|
| 字幕闪断 | 正空隙 <0.25 秒为错误；统一 cue 续显规则见[字幕](captions.md#字幕外框与底部) |
| 文字进场 | 相对落定字形宽度或缩放的过冲超主题上限为错误；明确声明 linear 或至少四个实际采样呈线性透明度／位移／缩放进入轨迹为错误 |
| 安全区 | 可见文字字形越出适用安全区为错误；字幕共用左右边距并保留自身纵向版面；1080 竖屏右界为 912 |
| 按钮列 | 竖屏 required 关键图形进入右侧保留列为错误，包含可见入场与退出；持续帧数保留在报告，短暂经过同样会被平台按钮遮挡。背景、装饰按自身用途追踪 |
| 片尾 | 名称／标语晚于实测指定词、整组与字幕外框间距小于 128 个基准像素、停留期间头像／名称／标语坐标变化为错误；间距按输出高度换算 |

自绘关键图形用 `withLayout` 声明 `required: true`；位图内部用已确认的保护区域声明实际关键部分。文字入口的 `textMotion` 和片尾的 `endCard` 元数据见[实现与记录](style-and-identity.md#实现与记录)。未声明的普通 fillText 可依据同一文字的实际轨迹与连续落定帧检测过冲和线性揭示；复杂文字身份、位图内部、缺少落定或片尾锚点的情况记 coverage/pending。描边、滤镜与保守位图外框继续按来源可信度复核。

静态 validate 校验 `layout` 声明结构、时间、父子关系、保护区的单镜头归属。渲染检查读取实际字形与填充路径，结合变换、裁切、透明度、绘制顺序和语义声明判断。按[布局接口](drawing.md#可选布局与追踪)登记关键内容及原视频保护区。

```bash
node .skill/scripts/video.mjs <slug> qa --layout
node .skill/scripts/video.mjs <slug> qa --layout --plan evidence/layout.json --from 1 --to 3 --all-frames
```

命令读取当前规格与已准备的素材／Production，保存 `out/layout-qa/report.json` 及最多 12 张问题帧；保持源码、规格与时间线原样。`--plan` 是本次检查使用的补充声明。报告列出源码与证据哈希、实际帧、时间、元素 id、文字／目标、坐标空间、交叠面积与比例、判定依据和预览区域。面积为路径交集的网格采样估计，严格判断同时使用精确路径与来源可信状态。

| 级别 | 规则与结果 |
|---|---|
| error | 可读字形相交；文字跨越图形边缘；required 内容越出适用画布／safe／parent 或被 clip 截断；后绘制内容覆盖阅读字形、字幕及已确认人脸／光标／操作目标／阅读保护区。返回非零，ok=false |
| review | 描边、滤镜、渐变、位图内部或保守外框造成的疑似冲突；未声明父子关系的包含。status=pending，按像素与用途复核 |
| coverage | 缺少所需保护区、未复核来源、附着目标缺失或位图缺少语义区域。status=pending；要求该项保护验收的镜头继续待复核 |
| diagnostic | 重心、错峰、镜头运动、静止、密度和占幅定位复核候选，工程退出码保持 0；工具运行失败另用非零码 |

alpha < 0.15 的元素暂不参与冲突判断；相机、离屏合成与 fade 的最终可见性共同计入。背景与装饰按绘制顺序排除；后绘制覆盖阅读文字仍检查。文字位于自己的 parent 卡片、目标一致的底层高亮／下划线可通过；合法 transition overlay 同时登记目标、时段、区域与非阅读状态。所有 overlay 继续接受字幕及已确认保护区检查。字幕外框和 8 个输出像素的周边作为避让区。

QA 默认检查请求区间的每帧。显式 `--step` 可作稀疏定位，进出场、切镜／转场、声明时间边界、保护关键帧、motion 区间和 `layout.windows` 仍按帧加密；最终门禁使用完整逐帧范围。报告保留采样范围与限制。自定义离屏画布须登记追踪；描边按包含线宽的外框复核；阴影（含零模糊偏移）、滤镜、特殊合成、putImageData直接像素写入、路径在多个变换下构建、位图／路径编码文字进入像素复核。源素材的语义覆盖由人工区域和已复核检测结果提供。

`layout.elements[].slot` 与 interval 相交时输出延后进入、提前退出、另选区域、重组信息四类候选，列出修改前后、可行性、读时及声音影响。候选保持 `requiresConfirmation: true`，确认具体方案后修改项目并重新核对声画。

构图在镜头落定后的阅读帧比较：追踪元素用可见外框面积 × 近似亮度对比 × alpha × 强调色权重估算；`centering-qa` 用可见像素的对比加权重心。水平 6%、垂直 8%、相邻跳变 15% 画高作为诊断起点，偏置、主体跟随和演示按用途解释；透明／空帧标 coverage。元素模型包含外框近似，编码像素与动态观察继续复核。

`layout.motion` 登记 scene、id、layer、enter、start/end，可附 group、needsStagger、mainEvent。lint 报告统一入场、缺少错峰、主体／次层／相机同时启动、仅淡入的镜头。稳定 id 的实际位置采样与 static 声明分别核对；自绘对象运动与自绘相机运动的来源由代码复核。缺少编排信息标 coverage。`layout.holds` 登记 start/end、purpose（reading／demonstration／hold）和 reason，静止诊断扣除已解释区间，保留剩余候选。

## 连续帧诊断

结构 qa、visual-check 的区域像素检查和连续编码诊断分别提供结构、局部材料与时间变化证据。当前编码通过 artifact 后运行：

```bash
node .skill/scripts/video.mjs <slug> diagnose --from 1 --to 3 --purpose motion --width 360
```

命令在 [from, to) 逐帧解码当前核心的固定帧率成片，每次 2–1200 帧，按源比例缩放。out/diagnostics/<首帧>-<末帧>/ 保存 report.json、带帧号及秒数的帧条和运动热图；报告绑定 MP4 哈希、runId、运行时、窗口、分辨率及阈值。长片分镜头和转场窗口运行。报告的 layout 分别记录 pass／error／pending；严格布局错误使 ok=false 并返回非零，运动与构图继续按诊断用途判读。

| 指标 | 计算与起始阈值 | 判读条件 |
|---|---|---|
| 运动区域 | 相邻 RGBA 帧按显示贡献比较，单像素最大通道差 > 8/255 计为变化；保存变化面积与外框 | 主体、相机、字幕和纹理均会贡献；背景运动可能掩盖主体停滞，按区域探针和帧条复核 |
| 静止帧对比例 | 变化面积 ≤ 0.001 为近静止，报告比例及连续停留区间 | motion 检查中后段推进；hold 支持反应定格，step 支持步进，reading 支持读时；低幅度动作需提高诊断尺寸或降低阈值 |
| 跳变候选 | 变化面积 ≥ 0.025、归一化平均差 ≥ 0.015，且超过局部中位差的 6 倍 | 比较前后各六对帧，排除相邻一对以识别孤立坏帧；上下文不足四对时保持待人工复核。硬切、字幕换项、步进、闪白与 transition 各按预期用途解释 |
| 运动热图 | 每个像素的变化帧对次数，以全图最高次数归一化显示 | 热图定位反复变化处；强度描述该窗口内的相对频度，窗口间比较使用报告的原始次数与阈值 |

`--pixel-threshold`、`--static-area`、`--jump-factor` 可调整上述定位阈值，实际值进入报告。阈值以缩略尺寸、编码噪声与动作规模解释，诊断提供复核候选。帧条最多 24 帧，报告列出选取帧和省略候选数；未展示候选按 pairs 和时间码继续抽帧。细线、小字和确定性以原尺寸复核。

文字与布局同步按当前源码求帧，字幕开关沿用 run.json，当前规格匹配的 out/audio/ 词表保存独立哈希。旧 `source-glyph-bounds` 保留几何定位；新增 layout 按上述路径、裁切、遮挡和声明规则检查。源渲染与编码像素各保留证据范围，原编码词表与音轨继续按声音证据核对。问题帧连到 review.md 的“观察 → 原因 → 修正 → 新编码复核”，完整观看和试听验证节奏与理解。

## 口播解说片常见漏项

适用条件：用本仓库引擎／代码渲染的口播解说竖屏成片（含信息卡、示意图叠字）。作者用本地剪辑软件剪自己拍的素材时，只强制第 2、5、6 条以及亮区字幕可读；第 1、3、4 条不套到这类本地剪辑流程。

交付前再过一遍（本期踩过的坑）：

1. 信息镜头的变化是否按词分拍，阅读与观察停留是否有明确用途（见[防死帧](style-and-identity.md#防死帧)、[信息卡与清单分拍](drawing.md#信息卡与清单分拍)）。
2. 字幕按句读拆成独立小句，显示文字去句读并保全数值与技术词；画面、SRT、VTT和高亮保持一致。每个有声字落在字幕区间内，实际字形上下居中，外框中轴线默认位于77.5%屏高；最长单行、多行与双语条目在平台预览中避开底部标题等信息和右侧互动按钮（见[字幕拆分](captions.md#字幕拆分)、[字幕几何](captions.md#字幕外框与底部)）。
3. 大量使用官方实拍 B-roll 时：源区间是否对应本镜信息，重叠区间是否有新的二次分析，裁前是否核对水印/HUD和使用依据（见[引用与复用](workflow.md#素材选择与生成视频)）。
4. 实拍垫底 + 代码叠字时：亮区字幕可读，大字进场与上一句字幕淡出错开（见[实拍 B-roll 与代码层](direction.md#实拍-b-roll-与代码层)）。字幕按普通叠加层验收，核对框外场景在字幕切换、空档和转场中保持完整；静镜按固定锚点验证坐标，语义动作按事件单独检查。
5. 单位与敏感词是否已跟锁定口播一致（公里等中国常见写法；尽量不出现「股票」字样，见[抖音发布](workflow.md)）——各端出片都守。
6. 片尾头像与个人 IP 落款：只在本片记录了用户确认时出现；头像素材、排版、颜色与动作符合[片尾规格](style-and-identity.md#片尾头像与个人-ip-落款)；名称与标语按「我是澄记，用计算机思维想现实。」的实测时间出现，口播结束后完整停留，字幕不压落款——各端出片都守。用户未确认或选择不采用时，成片不出现片尾卡，也不含「我是澄记，用计算机思维想现实。」，在正片内容的结论处结束。

## PPT 感与重复段落


逐项定位持续复现的页眉／页脚、相同中央卡片、相近镜长、整页淡化和全程轻幅缩放。循环流动、背景浮点、标题替换各有用途；信息推进由主对象的状态、关系、空间或情绪变化证明。自绘画面的实际编码为判断依据，elements 数量和 cameraMove 字段仅提供实现线索。

出现上述问题时，回到镜头编排表重写最影响体验的段落：确定保留对象，选择一个内容动词，设计清楚的起止构图，再用动作把两者接上。保留正确事实与可读标签，为主体让出足够画面。局部数值修正用于裁切、图层或时序问题；持续的布局和叙事重复需要修改段落设计。

每轮优先处理 1–3 个最影响观看的问题，写成“版本和时间 → 观察 → 影响 → 原因 → 修正 → 新编码复核”。事实错误、结构失真、证据失配与阅读障碍优先；接着处理主线、构图和节奏。复核修正段及相邻切点，适用项通过后进入下一阶段；轮数按缺陷和验证结果确定。

## 最终验收

逐项对照 events.md 的承诺、整合状态与主片时间码，核对选定主视觉、记忆点和重点运镜。完整动态粗剪、重点样片、最终主片分别记录自己的结果。正常速度全片观看与主观试听填写实际完成范围；缺口保持 pending。

已有影片沿用固定运行时和当时约定；新增方法的效果以实际采用记录判断。比较模型、技术路径或核心版本时保持输入、声音、时长和制作条件可比，声明实验范围。通过核心维护（由宿主按仓库核心维护规范执行）吸收已验证改进，成片修订和用户视觉验收各自记录。

## 结构化审片与本地交付

存在有效 `postprocess` 记录时，review、credits 与 deliver 共用实际后处理成品的路径、字节数、SHA-256、帧数与 fps。subject.postprocess 绑定完整记录及原始渲染身份；交付包 `artifact.mp4` 保存该成品，同时保存 `render-original.mp4` 与 `postprocess.json`，原渲染字幕侧车以 `render-captions.srt/vtt` 标明来源。声音 master 与 Production 渲染证据保留原渲染来源含义，最终有声状态依据后处理成品实测。新增后期素材纳入逐源权利清单。处理链、任一绑定文件或记录变化都会使原审片／批准失效；无后处理记录时沿用原交付结构。有效性核验失败时直接报错。

Production 正式编码可用 `review --subject` 读取当前审片对象，`review --schema review` 查询填写契约。对象固定成片路径、字节数与 SHA-256、run、运行时、输入快照、生产版本包、final 投影、渲染证据、实际声音源和 master，以及目录原件与实际字体。审片记录 reviewer、时间、工具、方法、帧区间及本片证据文件身份；参考另记实际观察时间区间、来源、提炼机制和采用镜头。

九项检查为 technical、narrative、camera、rhythm、captions、audibility、sync、quality 和 rights。完整视觉结论依据正常速度观看范围，声音可听性依据实际试听范围，同步结论依据声画一起观看范围。静帧、信号分析和文件检查保存各自观察事实。必需结论为 pass；无声成片的 audibility、sync 可附理由填 not_applicable。其余 revise、blocked 或范围缺口保存为待审稿，交付门禁据此保留待审状态。原创方案的 references 可为空；采用参考时记录实际观看或用户提供的研究，尚待完成的参考动态观察在对应检查中保留 blocked。

`credits --schema credits` 的逐源权利与署名覆盖当前对象中的目录原件、实际声音 take 和字体；记录原始与第三方权利状态、local-delivery 用途、限制评估、必要署名和依据。目录权利与已提交版本逐值核对，必要署名完整进入 attributionLines。动态 IO 和最终像素可见性的 partial 覆盖原句进入交付 knownLimitations。

```bash
node .skill/scripts/video.mjs <slug> review --subject
node .skill/scripts/video.mjs <slug> review --request evidence/structured-review.json
node .skill/scripts/video.mjs <slug> credits --request evidence/credits.json
node .skill/scripts/video.mjs <slug> deliver --request evidence/delivery-request.json
node .skill/scripts/video.mjs <slug> deliver --verify current
```

请求绑定当前 subject 及审片、署名文件的路径、字节数和 SHA-256，并通过 approvals 保存最终审批与撤销决策；没有对应决策时填空数组。决策沿 Production 契约引用本片 prompt-history 中的真实用户原文、条目位置与摘要。审批记录保存在交付请求中，当前编码消费的生产包保持固定，追加沟通沿已有历史前缀规则复查。

已有 approvalTasks 中的 final 审批采用 `deliveryApprovalHash(request, 'final')`，即 `productionHash(subject)`；delivery 审批采用 `deliveryApprovalHash(request, 'delivery')`，即请求中除 approvals 数组外全部内容的摘要。当前权威决策与请求审批共同核对适用性和撤销，内容变化后按当前摘要核对。交付范围为本地保存，其他外部操作各自核对已有授权。

交付在生产租约内复查全部当前来源与证据，复制独立文件并核验哈希，再保存版本清单和成功回执，最后原子切换 current。清单记录成片、生产版本、声音、审片、权利署名、复制文件和已知边界；复查同时核对原始文件与交付副本。失败保留有效旧 current 与失败回执；当前文件改变后，原审片和交付适用性回到待审。

参考记录按实际来源使用 normal-speed-playback、frame-inspection 或 provided-observations（用户提供的已完成研究）。提供观察时附原文与来源并注明本轮观看范围。原创方案可留空外部参考；当前成片的全片动态观看、听音和各项审片要求继续独立验收。
