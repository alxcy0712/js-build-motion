# 成片质量

以用户要求、受众、目标平台与 brief.acceptance 为验收依据。技术检查和创作检查各自保留结果：文件完整、配音存在和文字可读支持技术交付；叙事推进、构图变化、运动质感与节奏支持创作完成。创作检查仍有缺口时，交付注明待审范围，制作状态采用“已编码，创作待审”。

## 当前版本与观察范围

按[音视频流程](execution.md)运行 artifact，在 evidence/review.md 引用当前 MP4 的 SHA-256、runId 与固定运行时。抽帧、短片、解码、声轨和观看结论分别注明版本、时间码、方法和范围；交付前复核身份绑定。

机器检查、静帧、连续动态、正常速度观看、主观试听、用户验收各自记录。播放器 ended、完整解码和音频信号提供对应机器事实；速度、节奏、声音与理解依据实际视听观察。用户的观感反馈进入问题表，与原有机器结果共同保留。

文件改变后当前审片回到 pending，历史记录注明适用版本。仅封装变化时，核对解码画面、音频内容和时间轴的一致性，再保存新旧哈希映射并沿用对应观察；原有 pending 项继续保留。画面或时序变化时复核改动与相邻切点；变化范围未知时复核全片。

## 创作检查与预演退出条件

按[导演计划](direction.md)先审完整动态粗剪，再审正式素材的重点样片。以下各项以可定位观察填写 pass、revise 或 pending；分数可以辅助比较，同一轮的自评分需附依据。

创作结论回到本片约定的[首要体验与取舍](design-learning.md#先约定要发生的体验)，分别记录理解、识别或情绪的观察依据。模型评审、用户偏好与实际受众反馈注明各自来源；采用对照实验时引用对应版本、改变因素和支持范围。

| 维度 | 在当前编码中检查什么 |
|---|---|
| 开头与主线 | 开场的具体问题、动作或结果建立兴趣；观众能追踪同一任务、对象或关系 |
| 状态推进 | 每段有起始、动作与结果；入场后的中后段继续推进，停留支持阅读或情绪 |
| 构图与景别 | 并排比较全部镜头的主体占比、关系和留白；近景、全貌或稳定图解按内容形成节奏 |
| 动画质感 | 触发、加速、接触、次级响应与落定有清楚分工；连续改目标时位置和速度接续 |
| 相机与转场 | 起止构图之间有可见的发现；焦点稳定、分层有作用、相邻镜头接力明确 |
| 声音与阅读 | 实测语义词、动作和音效对齐；音乐强弱与停顿有层次；360px 宽下主体和字幕可读 |
| 身份与事实 | 品牌地标、人物、结构、方向、单位和比例稳定；示意与真实证据口径清楚 |
| 个人包装 | 按[固定识别与组件验收](visual-identity.md#审片验收)核对实际选用（含片尾卡是否经用户确认、是否与片尾口播同步，未采用时有无残留收尾口播）：字体层级、黄色标记、容器与同类进退场一致，字幕／人物条／来源互相避让，最拥挤镜头和代表性变体有当前编码证据 |
| 动效意义与文字权重 | 按[共用动效标准](motion-language.md)回答主题、镜头意义、动作／运镜理由；对象和关系支持主张，大字承担明确的提问或结论 |
| 色彩与强弱 | 品牌黄和变量颜色职责稳定；换色有状态依据，正文对比、手机可读性、亮暗闪烁与强动效后的阅读停留逐段检查 |
| 现实规则 | 写实／示意／抽象口径明确；受力、接触、尺度、透视与播放方向符合本镜模型，教学简化有说明 |
| 外部资料与复用 | 事实来源、权利范围、必要署名和目标平台规则分别核对；同源再次使用记录可见的新分析，必要标识或比较基准注明持续用途 |

为承担解释的镜头做一次辅助检查：暂时遮住标题与装饰大字，记录还能看清的对象、变化和结果；文字推导及引文保留其必要文本。结果依赖口号时补对象、动作或证据。再比较复杂转场与普通切镜的理解收益，保留有明确作用的版本。上述检查辅助分镜修正，完整声画观看继续验证主题理解与惊喜出现的位置。

三种取样各解决一类问题：全片联系表看构图分布；动作与切点的连续帧条看跳变、重影、遮挡和中间态；正常速度播放看速度、停留和注意力。联系表分页覆盖全片，记录每页时间范围。快速动作按实际帧率取连续帧；编码后复核真实字体与边缘清晰度。主体细节按[精确几何](reference-geometry.md)检查，字幕按[语义分镜](captions-and-shots.md)检查。

## 连续帧诊断

结构 qa、visual-check 的区域像素检查和连续编码诊断分别提供结构、局部材料与时间变化证据。当前编码通过 artifact 后运行：

```bash
node .skill/scripts/video.mjs <slug> diagnose --from 1 --to 3 --purpose motion --width 360
```

命令在 [from, to) 逐帧解码当前核心的固定帧率成片，每次 2–1200 帧，按源比例缩放。out/diagnostics/<首帧>-<末帧>/ 保存 report.json、带帧号及秒数的帧条和运动热图；报告绑定 MP4 哈希、runId、运行时、窗口、分辨率及阈值。长片分镜头和转场窗口运行。报告的 ok 表示诊断执行与输入身份通过，观感状态继续由审片填写。

| 指标 | 计算与起始阈值 | 判读条件 |
|---|---|---|
| 运动区域 | 相邻 RGBA 帧按显示贡献比较，单像素最大通道差 > 8/255 计为变化；保存变化面积与外框 | 主体、相机、字幕和纹理均会贡献；背景运动可能掩盖主体停滞，按区域探针和帧条复核 |
| 静止帧对比例 | 变化面积 ≤ 0.001 为近静止，报告比例及连续停留区间 | motion 检查中后段推进；hold 支持反应定格，step 支持步进，reading 支持读时；低幅度动作需提高诊断尺寸或降低阈值 |
| 跳变候选 | 变化面积 ≥ 0.025、归一化平均差 ≥ 0.015，且超过局部中位差的 6 倍 | 比较前后各六对帧，排除相邻一对以识别孤立坏帧；上下文不足四对时保持待人工复核。硬切、字幕换项、步进、闪白与 transition 各按预期用途解释 |
| 运动热图 | 每个像素的变化帧对次数，以全图最高次数归一化显示 | 热图定位反复变化处；强度描述该窗口内的相对频度，窗口间比较使用报告的原始次数与阈值 |

`--pixel-threshold`、`--static-area`、`--jump-factor` 可调整上述定位阈值，实际值进入报告。阈值以缩略尺寸、编码噪声与动作规模解释，诊断提供复核候选。帧条最多 24 帧，报告列出选取帧和省略候选数；未展示候选按 pairs 和时间码继续抽帧。细线、小字和确定性以原尺寸复核。

文字诊断同步按当前源码求帧，字幕开关沿用 run.json，当前规格匹配的 out/audio/ 词表在报告中保存独立哈希；原编码词表与音轨的对应仍按声音证据复核。报告范围为 source-glyph-bounds：主画布和管线 incoming 离屏画布的 fillText/strokeText，实测字形外框、相机变换、drawImage 目标变换与显式源裁框。字形越过画布或在源画布裁掉时记录时间码。装饰大字与转场中的越界按本片用途核对。任意 clip 路径、图形遮挡、阴影、滤镜、位图/路径文字和未经 trackTextBounds 登记的本片离屏画布进入像素复核；旋转后的矩形为保守外框。需要登记本片离屏文字时按需复制 text-bounds 组件，在初始化时 trackTextBounds(ctx)，重画前 reset；缓存画布保留对应 draws。

原尺寸 source-glyph-bounds 与缩略编码帧差各保存覆盖范围。用正常标签、边缘裁切、相机缩放、离屏转场和装饰大字检验定位；遮挡夹具核对已声明的覆盖边界。诊断结果连到 review.md 的“观察 → 原因 → 修正 → 新编码复核”，完整观看和试听继续检查节奏与理解。

## 口播解说片常见漏项

适用条件：用本仓库引擎／代码渲染的口播解说竖屏成片（含信息卡、示意图叠字）。作者用本地剪辑软件剪自己拍的素材时，只强制第 2、5、6 条以及亮区字幕可读；第 1、3、4 条不套到这类本地剪辑流程。

交付前再过一遍（本期踩过的坑）：

1. 信息镜头的变化是否按词分拍，阅读与观察停留是否有明确用途（见[防死帧](styles.md#防死帧)、[信息卡与清单分拍](motion-design.md#信息卡与清单分拍)）。
2. 字幕按句读拆成独立小句，显示文字去句读并保全数值与技术词；画面、SRT、VTT和高亮保持一致。每个有声字落在字幕区间内，实际字形上下居中，外框中轴线默认位于77.5%屏高；最长单行、多行与双语条目在平台预览中避开底部标题等信息和右侧互动按钮（见[字幕拆分](captions-and-shots.md#字幕拆分)、[字幕几何](captions-and-shots.md#字幕外框与底部)）。
3. 大量使用官方实拍 B-roll 时：源区间是否对应本镜信息，重叠区间是否有新的二次分析，裁前是否核对水印/HUD和使用依据（见[引用与复用](assets.md#外部资料的引用与复用)）。
4. 实拍垫底 + 代码叠字时：亮区字幕可读，大字进场与上一句字幕淡出错开（见[实拍 B-roll 与代码层](cinematography.md#实拍-b-roll-与代码层)）。代码主题镜头按固定内容比较底部与字幕区像素，验证静色带对扫光、颗粒和转场的覆盖；静镜按固定锚点验证坐标，语义动作按事件单独检查。
5. 单位与敏感词是否已跟锁定口播一致（公里等中国常见写法；尽量不出现「股票」字样，见[抖音发布](douyin-publishing.md)）——各端出片都守。
6. 片尾头像与个人 IP 落款：只在本片记录了用户确认时出现；头像素材、排版、颜色与动作符合[片尾规格](visual-identity.md#片尾头像与个人-ip-落款)；名称与标语按「我是澄记，用计算机思维想现实。」的实测时间出现，口播结束后完整停留，字幕不压落款——各端出片都守。用户未确认或选择不采用时，成片不出现片尾卡，也不含「我是澄记，用计算机思维想现实。」，在正片内容的结论处结束。

## PPT 感与重复段落


逐项定位持续复现的页眉／页脚、相同中央卡片、相近镜长、整页淡化和全程轻幅缩放。循环流动、背景浮点、标题替换各有用途；信息推进由主对象的状态、关系、空间或情绪变化证明。自绘画面的实际编码为判断依据，elements 数量和 cameraMove 字段仅提供实现线索。

出现上述问题时，回到镜头编排表重写最影响体验的段落：确定保留对象，选择一个内容动词，设计清楚的起止构图，再用动作把两者接上。保留正确事实与可读标签，为主体让出足够画面。局部数值修正用于裁切、图层或时序问题；持续的布局和叙事重复需要修改段落设计。

每轮优先处理 1–3 个最影响观看的问题，写成“版本和时间 → 观察 → 影响 → 原因 → 修正 → 新编码复核”。事实错误、结构失真、证据失配与阅读障碍优先；接着处理主线、构图和节奏。复核修正段及相邻切点，适用项通过后进入下一阶段；轮数按缺陷和验证结果确定。

## 最终验收

逐项对照 events.md 的承诺、整合状态与主片时间码，核对选定主视觉、记忆点和重点运镜。完整动态粗剪、重点样片、最终主片分别记录自己的结果。正常速度全片观看与主观试听填写实际完成范围；缺口保持 pending。

已有影片沿用固定运行时和当时约定；新增方法的效果以实际采用记录判断。比较模型、技术路径或核心版本时保持输入、声音、时长和制作条件可比，声明实验范围。通过[核心维护](maintenance.md)吸收已验证改进，成片修订和用户视觉验收各自记录。

## 结构化审片与本地交付

Production 正式编码可用 `review --subject` 读取当前审片对象，`review --schema review` 查询填写契约。对象固定成片路径、字节数与 SHA-256、run、运行时、输入快照、生产版本包、final 投影、渲染证据、实际声音源和 master，以及目录原件与实际字体。审片记录 reviewer、时间、工具、方法、帧区间及本片证据文件身份；参考另记实际观察时间区间、来源、提炼机制和采用镜头。

九项检查为 technical、narrative、camera、rhythm、captions、audibility、sync、quality 和 rights。完整视觉结论依据正常速度观看范围，声音可听性依据实际试听范围，同步结论依据声画一起观看范围。静帧、信号分析和文件检查保存各自观察事实。必需结论为 pass；无声成片的 audibility、sync 可附理由填 not_applicable。其余 revise、blocked 或范围缺口保存为待审稿，交付门禁据此保留待审状态。参考实际观看区间待确认时，草稿 references 保持空数组；正式交付要求具体参考片的正常速度观看证据。

`credits --schema credits` 的逐源权利与署名覆盖当前对象中的目录原件、实际声音 take 和字体；记录原始与第三方权利状态、local-delivery 用途、限制评估、必要署名和依据。目录权利与已提交版本逐值核对，必要署名完整进入 attributionLines。动态 IO 和最终像素可见性的 partial 覆盖原句进入交付 knownLimitations。

```bash
node .skill/scripts/video.mjs <slug> review --subject
node .skill/scripts/video.mjs <slug> review --request evidence/structured-review.json
node .skill/scripts/video.mjs <slug> credits --request evidence/credits.json
node .skill/scripts/video.mjs <slug> deliver --request evidence/delivery-request.json
node .skill/scripts/video.mjs <slug> deliver --verify current
```

请求绑定当前 subject 及审片、署名文件的路径、字节数和 SHA-256，并通过 approvals 保存最终审批与撤销决策；没有对应决策时填空数组。决策沿 Production 契约引用本片 prompt-history 中的真实用户原文、条目位置与摘要。审批记录保存在交付请求中，当前编码消费的生产包保持固定，追加沟通沿已有历史前缀规则复查。

已有 approvalTasks 中的 final 审批采用 `deliveryApprovalHash(request, 'final')`，即 `productionHash(subject)`；delivery 审批采用 `deliveryApprovalHash(request, 'delivery')`，即请求中除 approvals 数组外全部内容的摘要。当前权威决策与请求审批共同核对适用性和撤销，内容变化后按当前摘要核对。交付范围为本地保存，其他外部操作各自核对已有授权。

交付在生产租约内复查全部当前来源与证据，复制独立文件并核验哈希，再保存版本清单和成功回执，最后原子切换 current。清单记录成片、生产版本、声音、审片、权利署名、复制文件和已知边界；复查同时核对原始文件与交付副本。失败保留有效旧 current 与失败回执；当前文件改变后，原审片和交付适用性回到待审。
