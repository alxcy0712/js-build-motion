## 2. 为什么看起来顺：六条技法

1. **把「切」换成「变」**。上一镜头最后一个元素直接变成下一镜头的第一个元素（圆环变花、花心变星系）。观众视线落点不变，所以不觉得断。工程上就是：两镜头共享一个「焦点元素」，转场以它为中心放大/形变。→ 本次实现 `focus` + `zoomIntoElement`。
2. **相机始终在动，但很慢**。三维产品片每个镜头都有 2–6% 的推或移，起止都有减速，从不匀速。→ 本次实现关键帧相机 `cameraPath`（默认缓入缓出，zoom 走对数插值，起止速度为 0）。
3. **版式不变，内容在变**。Sherwood 的 01–04 段、导数课的每一步，标题位置、卡片位置、配色全程不动，只换里面的字和数据。版式稳定带来的「顺」比任何转场都强。→ 已有：风格 token + 安全区；建议后续加「同版式换内容」的镜头模板。
4. **大全景 → 局部 → 回到全景**。三维片和导数课都用这个三段式：先交代全局，再钻进细节讲，最后拉回全局收尾。→ `cameraPath` + `focus` 可直接表达。
5. **节奏跟着信息密度走**。讲解片一屏一个概念，停留到读完为止；MV 才按拍切。字没读完就切是最常见的「不高级」。→ 本次实现 `shot-timing`（按字数/词数算最短停留，节拍只向后吸附）和 `SHOT_TOO_SHORT_FOR_TEXT` 告警。
6. **素材片的「质感」来自统一调色和缓慢推拉**。西湖片的素材来源各异，但每段都是慢推/慢摇 + 统一的冷暖和暗角，章节标签固定在左上。→ 本次实现素材片段层（ken-burns / 裁切 / 变速 / 调色 / 暗角）。

## 3. 镜头放在哪、怎么推进

- **注视点不在正中**。产品特写和讲解图示的注视点通常在画面中上（约 0.42–0.47 高度）或三分线上；竖屏把主体放在 0.40–0.45，给底部字幕和平台 UI 留位置（与 `SAFE_AREA` 一致）。
- **推镜幅度很小**。单镜头内的 zoom 变化多在 1.0→1.08 之间；超过 1.3 就会被看成「转场」而不是「运镜」。
- **摇镜和推镜不同时开始**。三维片常见先推后摇，或者摇到位后再轻推，两种运动错开 0.3–0.5 秒，不会显得乱。`cameraPath` 用多个关键帧表达。
- **环绕（orbit）= 横移 + 轻微旋转**。2D 里用 x 变化配合 ±1° 以内的 rotate 就能模拟；远景层用 parallax < 1、前景 > 1（`applyCameraPose` 的 parallax 参数）。
- **钻入的终点是元素充满画面**。放大倍数 = 0.9–1.1 ÷ 元素占画面的比例，再从同一点展开新镜头（`zoomToFill`）。

## 4. 三类片的拆法

### 4.1 讲解/口播（explainer）
- 固定机位或极慢推；一屏一个概念；**元素逐步搭建**（先坐标轴，再曲线，再切线，再标注）。
- 关键数字和公式用强调色局部高亮，不用整屏闪。
- 时长由文字和旁白决定：先写稿，再用 `planShotTimings` 排时间轴，最后让画面配合，而不是反过来。
- 本仓库对应：`theme_stage` + `headline/kicker` + `cameraPath`（慢推）+ `shot-timing`。

### 4.2 动画（animation）
- 一个角色/造型贯穿全片；场景之间用**形变或钻入**衔接，而不是切。
- 每个镜头内部至少有一层在动（呼吸、漂浮、粒子），停住就会显得「死」（已有防死帧 QA）。
- 本仓库对应：`focus` + `zoomIntoElement`、IP 演员角色（≤512px，不放大）、liveness 微运动。

### 4.3 剪辑已有素材（footage edit）
- 先定结构（章节、旁白时长），再选素材；每段素材统一调色，慢推/慢摇 4–8 秒。
- 变速只做慢放（0.5–0.8×）制造质感，快放留给转场。
- 章节标签、字幕位置全片固定。
- 本仓库对应：`environment: 'footage'` + `footage.{src,in,speed,crop,kenBurns,color}`，素材只能来自素材根目录（防越界）。

## 7. 分镜默认值（数字即规范）

| 项 | 默认 | 代码 |
|---|---|---|
| 竖屏讲解屏时长 | 2.5–5s（按读完所需时间自动定） | `SHOT_LENGTH.explainer`、`minShotSeconds` |
| 强调大字屏（≤ 6 字/词，巨型数字、一句结论） | 2–3s | `SHOT_LENGTH.emphasis` |
| 讲解推镜 | 1.0 → 1.10–1.15，3–4s | `CAMERA_GRAMMAR.normal`、`cameraMove('normal', …)` |
| 强调推镜 | 1.0 → 1.20–1.30 | `CAMERA_GRAMMAR.emphasis` |
| 开场 logo/标题 | 反向拉 1.2 → 1.0 | `CAMERA_GRAMMAR.openingPull` |
| 镜头内 zoom 上限 | 1.5；更大只在穿透式转场（zoomIntoElement / scaleThrough）里 | 超出时告警 `CAMERA_ZOOM_PUNCH_ONLY` |
| 环境漂移地板 | ≈1.03，由风格 liveness 负责，和作者运镜分开叠加 | `themes/liveness.ts` |
| 开场 | 黑底上 cutOnBeat 直接切到最强元素；或先旁白再卡点切 | `transition: 'cutOnBeat'` |
| 首选转场 | zoomIntoElement 钻进一个 UI 图标，再从它里面拉出下一屏；scaleThrough 用于细节 → 大字；其余以直切为主 | `focus` + `transition` |

spec 写法（运镜一律写数字）：

```json
{ "id": "s2", "start": 2.5, "end": 5.5, "environment": "theme_stage", "headline": ["一屏一个概念"],
  "cameraPath": { "keys": [{ "t": 0, "zoom": 1.0 }, { "t": 2.4, "zoom": 1.08 }] },
  "focus": { "x": 0.42, "y": 0.40, "w": 0.16, "h": 0.09 } }
{ "id": "s3", "start": 5.5, "end": 8, "environment": "footage", "transition": "zoomIntoElement",
  "footage": { "src": "clips/lake.mp4", "in": 2, "speed": 0.75,
               "kenBurns": { "from": { "x": 0.4, "y": 0.5, "zoom": 1.1 }, "to": { "x": 0.6, "y": 0.45, "zoom": 1.2 } },
               "color": { "exposure": 0.1, "contrast": 1.05, "saturation": 1.1, "temperature": 0.2, "vignette": 0.4 } } }
```

- `focus` 写在**被钻入的镜头**上，下一镜头用 `zoomIntoElement` 时以它为中心。
- 素材 `src` 相对渲染时传入的 `assetRoot`（`createSpecRenderer({ assetRoot })`），越界路径和符号链接逃逸都会被拒绝；视频抽帧缓存在 `output/.cache/footage/`。
- 转场只能用当前风格允许列表里的（minimal 已加入 zoomIntoElement）。IP 只用 `ip.role: identity | actor`，不放大。
- 冒烟：`node .skill/engine/scripts/motion-smoke.ts [outDir] [vertical|horizontal]`，产物默认写入仓库根 `output/motion-smoke/`。
