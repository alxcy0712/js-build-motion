# 短字幕与语义分镜

旁白段落承载连续表达，字幕条目承载一次阅读，镜头承载一个可见事件。用同一脚本与实测配音时间连接这三层：标点提供字幕断点，信息变化决定镜头与动作的推进。

## 字幕拆分

先按逗号、句号、问号、感叹号、分号与冒号识别语义停顿，再检查完整词组。人物与模型名称、数字与单位、比较关系和因果限定保持可读的组合；枚举中的短词可合并阅读。中文讲解通常从每条约 10–20 字、每次一至两行试排，结合字号、画幅、手机显示与语速调整。

引擎的 buildCaptionTrack 按标点和可用宽度拆分单语字幕，优先保留实测词边界；短词与不足 0.8 秒的条目在宽度允许时合并。长句末尾的孤词通过前移词组边界补足读时。常规逗号、句号成为条目末尾的断点，原文字词、名称和数值保持完整。小数、千位数、版本号与 URL 内的符号属于对应词组。超长完整词组和很快的短句进入 QA 复核。

字幕起止必须取该小句自身在词级时间戳里的首字开始与末字结束，再加阅读余量并核对句间停顿。按标点拆小句时，禁止把同一整句的起止时间套给后面几个小句——那会让后半句字幕在开头一闪而过，真念到时画面反而是空的。交付前用词级时间戳逐字核对：每个有声字的中点都必须落在某条字幕的显示区间内；单条字幕可读时长建议 ≥0.8 秒，不足则与相邻短词合并。缺少词级时间或词表与脚本匹配失败时，估算时间只用于排版预览，实际同步保持待复核。画面内字幕、SRT 和 VTT 使用同一 cue 列表；词级高亮保留原脚本的标点与空格。双语先准备语义对应的短句，逐条核对主字幕、译文和声音；引擎保留整段译文的既有对应关系，并对长段给出复核提示。本仓库引擎 `buildCaptionTrack` 已按词级边界计时；单片自写渲染脚本若自造字幕轨，必须复用同一规则并做上述逐字核对。

字幕改片复用原音轨和词级时间，保留原时长与配音语速；实测、封装和身份核对按[音视频流程](execution.md)。字幕换行、每条时长和实际字号在当前编码中核对。

## 分镜与画面推进

从台词中找出问题、动作、比较、结果、转折与情绪落点，写成语义节拍。每个节拍明确观众此时应理解什么，以及对应的起始状态、可见变化和落定结果；长段落据此安排子镜或同镜内的阶段动作。字幕切换可以继续同一动作，也可以交接焦点；镜头切换配合信息与情绪的变化。

在本片 events.md 增加需要的节拍行：

| 实测时间 / 台词子句 | 信息推进 | 可见动作与结果 | 焦点 / 景别 | 相邻节拍接力 / 阅读停留 |
|---|---|---|---|---|
| 输入到来 | 建立任务 | 输入沿路径抵达路由器 | 输入细节 → 路由关系 | 同一输入继续流动 |
| 选择部分专家 | 解释选择 | 少数分支点亮、数据抵达专家 | 跟随分支 → 局部结构 | 保留输入与专家的连线 |
| 容量与开销 | 呈现取舍 | 全貌保留，激活部分获得强调 | 拉远到完整关系 | 结论与限定口径阅读 |

表中机制用于解释选择，实际题材按自身动作与证据设计。人物故事可用视线、动作和环境变化接力，产品展示可用细节、操作和结果接力。完整旁白可以跨视觉切点连续播放，其窗口由下一段旁白和片尾限定。导演项目修改后重新 direct compile，核对计划与 spec；同镜内的语义节拍由本片自绘代码按父镜头时间求值，实际采用方式写入事件表。

## 中文语义事件排程

直接复用 out/audio/ 或 out/audio-preflight/ 的 narration-timing.json 与原词表；词时间为相对影片开头的实测秒数。先核对 specHash 和中文字词对应，再把指定词的 start/end 写入 events.md。中文词组可能横跨多个词项，采用首项 start 与末项 end；目标词位于一个更长词项内部时，整项时间只提供范围，峰值通过实际试听定位并登记偏移。缺失或失配的词时间沿用现有估算预览与 pending 流程。

每个语义事件登记三个可复核时点：

| 时点 | 排程与求帧 |
|---|---|
| 首次显现 firstVisible | 先写“可见”的条件，如主词达到正常字号与可读透明度；在语义词开始前完成必要准备。要求时刻之后首次发生时，取 ceil(t × fps)；记录实际帧及偏移 |
| 强调峰值 emphasisPeak | 取指定词的实测重音；原词 start 可作为初始锚点。用 round(t × fps) 对齐最近帧，误差上限半帧；放大、位移或颜色达到峰值后回到可读状态 |
| 动作完成 actionComplete | 数值落定、连线抵达或最后一项呈现完成；用 ceil(t × fps) 对齐，固定时间求值在该帧及随后帧保持最终状态 |

准备、主动作与落定各自写明时长；若动作必须在关键词处完成，从 actionComplete 反推开始时间。首次显现与强调峰值可以在同帧，也可以先显现再强调，关系依据本句含义。字幕的逐词高亮继续使用 buildCaptionTrack/activeWordIndexAt 的原词时间。

完整读时从最终内容完成开始计算。清单用 max(所有项 actionComplete)，数据比较用最终精确值与必要单位、条件全部落定的时刻；readingEnd = complete + 本片选定读时。以实际帧差计算读时，例如最后一项第 72 帧完成、第 108 帧结束阅读，在 24fps 下完整读时为 1.5 秒。下一动作或切点落在 readingEnd 之后；早于完成的逐项读时仍可帮助理解，各自记录。

用固定帧核对首次显现前一帧、显现帧、峰值两侧、完成帧与阅读结束前一帧，再正常速度播放原配音。事件表保存语义词或词项范围、实测锚点、偏移、三个实际帧、readingEnd 与用途；完整清单和数字最终状态分别核对。音效接触、音乐重音及编码身份按[音视频流程](execution.md)复核。

## 艺术感与长镜头复核

选定服务主题的构图、材质、光线与运动母题，并在关键段落落实。概览建立空间或关系，细节展示变化，结果镜头保留阅读与情绪停留。前景、中景、背景各有运动或光影作用，主体动作与相机路径围绕同一焦点排时序；运镜按[电影化运镜](cinematography.md)验证。标题、说明和来源占据必要的阅读位置，视觉权重集中于当前事件。

逐段检查开头、四分点、中点与结尾：记录新信息出现、焦点交接、主体变化和静止停留的用途。前几秒揭示结束后，后半段应继续完成讲解、动作、尺度发现或有理由的阅读停留。相邻镜头比较主体、关系、景别与留白；把原有的列表改为按讲解顺序发生的过程，把技术结论落实为选择、流动、压缩、比较或验证的可见结果。

总帧数按实际成片的时长和 fps 核对，同时报告秒数、帧率和分辨率。艺术感与信息推进依据当前编码的连续观察评价；帧数用于描述成片规格。

## 验证

代表性短样片覆盖一组短字幕切换、一段长旁白的内部推进、重点机制动作和相邻切点。用原配音正常速度播放，核对字幕闪现、提前或滞后、主体遮挡、局部裁切、转场重影和结论停留。结构 QA 报告字幕条数、最长文本、最短停留和估算条目；真实字体测量与编码画面确认每次行数、字号及安全区。

在 evidence/review.md 保存当前视频身份、字幕与节拍时间码、观察范围、问题和复核结果。字幕、声音与动态审片分别标注实际状态；具体规则和镜头修正通过样片后再进入主片。

## 按 TTS 时间戳拆分镜

适用条件：口播稿已锁定（见[锁定规则](douyin-publishing.md#锁定规则)），配音已产出逐字或逐词时间戳（豆包另有句级 sentences，见[音视频流程](execution.md)）。时间戳出来之后再拆分镜。

- **句间切点**：上一句末字结束与下一句首字开始之间空隙的中点（`gapMidpointCuts`，`src/motion/shot-timing.ts`）。
- **句内切点**：下一短语首字开始前约 0.05 秒，不早于上一短语末字结束（`phraseCut`）。
- **卡点**：强调词的大字、动作、音效对齐该词首字时间；精确到帧的排程按上文[中文语义事件排程](#中文语义事件排程)。与音乐拍点的吸附见 `snapCutsToBeats`，只做小幅微调。
- **字幕**：与口播同步出入，不提前、不拖后；每条至少约 0.8 秒（拆分规则见上文[字幕拆分](#字幕拆分)）。
- **节奏默认**：竖屏解说每镜 2.5–5 秒、大字强调镜 2–3 秒、以直切为主、运镜写数字起止，默认值与开头三秒做法见[分镜默认值](motion-breakdown.md#7-分镜默认值数字即规范)，按片调整。

分镜表在本片 evidence/ 保存，每镜一行：

| 列 | 要求 |
|---|---|
| 镜号 / 时长 | 起止秒数（来自 TTS），保留两位小数 |
| 景别构图 | 特写 / 中景 / 全景，主体位置 |
| 镜头运动 | 写数字起止，如「推 1.0→1.08，2.4s」；不写缓动 |
| 画面动效 | 元素如何入场、变化、离场 |
| 口播 | 锁定稿原句，不改一字 |
| 字幕 | 与口播一致，按断句拆条 |
| 屏幕大字 | ≤10 字，只从原文截连续短句；截不出就列选项让作者挑 |
| 转场 | 当前风格允许的 transition：blurDissolve / riseFade / maskWipeUp / scaleThrough / cutOnBeat / whipPan / zoomIntoElement |
| IP 出场 | identity（片尾署名）或 actor + 具体动作；不需要就不出场（[个人 IP 使用规则](styles.md#个人-ip-使用规则)） |
| 素材 | 路径和出入点 |
| 生成 / 代码分层 | 生成视频镜头必填：生成部分（纯动作）｜代码部分（文字 / UI / 光效），规则见[生成视频分层合成](assets.md#生成视频分层合成) |

版面：字幕贴底、大字与字幕固定间距、主画面在视觉中心，数值见[竖屏版面默认](styles.md#竖屏-916-口播版面默认)；章节导航条（如有）放在顶部安全区内。画面合规见[合规清单](douyin-publishing.md#合规清单发布前逐条过)。

锁定：分镜交给制作后锁定，审片阶段只改时间戳和叠字，不回改分镜；增删镜头或改变生成/代码分层时才重拆，并在 NOTES.md 记录原因。

验证：用原配音正常速度播放切点附近各 1 秒，核对切点落在句间空隙、字幕无闪现、强调词与大字/动作同帧；分镜表口播列与锁定稿逐字一致；用词级时间戳跑一遍「有声字是否都落在字幕显示区间」检查，结果写入本片 evidence/review.md。

### 补录口播后的分镜回填
只改少数句子、其余句子不重录时：新时间戳出来后，从第一句改动的镜头起整段重算切点与镜长，改动之前的镜不动；屏幕大字、信息卡上的单位与数字与新口播一致（中国常见单位写法见[抖音发布](douyin-publishing.md#合规清单发布前逐条过)）。分镜表附一张「素材使用对照」：每个 B-roll 文件列出使用镜号与源出入点，同一源区间不得分给两镜，同一文件多用时区间不得重叠（细则见[官方 B-roll 不重复](assets.md#官方-b-roll-不重复)）。
