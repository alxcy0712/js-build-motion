# 风格选择

表中列出当前引擎已注册的主题预设。每片的视觉设计与效果组合按共用标准确定；新增内置主题需同步注册、品牌配置和校验。

| theme | 名称 | 关键 token | 适用 |
|---|---|---|---|
| `minimal`（默认） | 极简 | 底 #000、字 #F5F5F7、品牌黄 #FFC712；Inter + 中文字体栈；竖屏 hero 132；文字弹簧 k100 c25（零过冲）；进场 0.9s、holdMin 1.2s | 机制解释、证据对照、观点表达、品牌片尾 |
| `kinetic` | 炫酷 | 底 #05060A、品牌黄 #FFC712 + 蓝紫 #5B3DF5；Inter Tight + 中文字体栈；竖屏 hero 168；文字进场 k380 c28（过冲 ≤4%）；进场 0.45s、holdMin 0.6s | 状态变化、操作结果、效率对比、产品与机制揭示 |

字号、停留、BPM 和转场列表提供预设起点。镜长按实测台词、动作与读时决定，主体和关系承担讲解；各类风格的强度选择和共同验收按[动效语言与制作标准](motion-language.md)。

所有风格共用安全区：竖屏 上220 / 下520 / 左72 / 右168；横屏 上72 / 下96 / 左右120。安全区约束字幕以外的文字和主体。

## 按任务选择表现方式

先确定观众要辨认的对象、需要看清的变化和最后要记住的结果，再提出风格方案。本节描述当前两种主题的创作取向；每片主题沿用下文的选择与快照规则。网站标签、作品标题和明暗配色分别提供检索线索，采用时按实际信息任务判断。

| 内容任务 | kinetic 的组织方式 | minimal 的组织方式 | 选择依据 |
|---|---|---|---|
| 产品发布、功能亮点 | 用一次操作带出结果，在关键发现处放大尺度与颜色反差 | 保留真实界面骨架，聚焦输入、反馈和完成状态 | 核心卖点能由短动作证明时适合 kinetic；操作细节需要逐步辨认时适合 minimal |
| 机制、教程、技术流程 | 用对象沿路径传递、聚合或分解揭示关键机制 | 固定空间、坐标和标签，按因果逐步更新局部 | 需要记住变化方向时采用较强动作；需要追踪多个变量时优先稳定布局 |
| 跑分、数据、证据比较 | 揭示差异时集中强调，随后落定到完整对照 | 保持基线、单位、列宽和比较条件，依次指出差异 | 证据阅读段保留稳定参照；效果强度随数据密度降低 |
| 品牌、身份、情绪收束 | 内容母题回归，主动作完成后形成明确落点 | 通过留白、字重和精确对齐收束注意力 | 结尾的身份、结论和必要署名各有读时 |

### kinetic：用变化建立记忆点

1. **建立对象**：先让观众认出一个具体对象、操作或问题，给贯穿母题指定身份和作用。轮廓、颜色、位置或路径承担接力线索。
2. **证明变化**：一次主要动作承载一个可核对的结果。用形状接力、前后景尺度差、局部放大或文字重组突出本段动词；文字的形变对应压缩、分组、展开等含义。
3. **安排强弱**：普通段落用较少层次，关键发现集中投入形变、换色或运镜。音乐段按实测重音安排触发、峰值与落定，阅读段以读完为界。
4. **回到结果**：动作收束后，主体、完整数值和单位清楚呈现，再把结果交给下一镜。母题回归时带回已经发生的变化。

将大字、背景变化、相机加速分配到不同的注意力交接时点。装饰层在证据进入时降低权重。图表数据、品牌轮廓与刚性部件保持各自的约束；夸张集中在允许变化的图形层。短展演的逐拍换形适合展示运动技巧，知识解释的节奏由因果与读时决定。

### minimal：用稳定参照显现差异

1. **建立参照**：固定主体框架、图表坐标或对照列，先交代对象身份、输入条件和单位。留白将当前问题与辅助信息分开。
2. **局部推进**：一次操作更新相关字段、路径或部件，其他参照继续可见；前一步结果保留为下一步的依据。
3. **展示证据**：把标签、数值和图形绑定到同一状态。比较使用相同刻度、单位、精度与对齐方式，完整结果出现后开始计算读时。
4. **形成结论**：用局部强调或精简结论指出变化，保持清晰、稳定的结果画面。需要看细节时局部放大，随后回到原有空间。

质感来自比例、字重、间距、边缘与时序的精确配合。品牌黄集中指向当前变量或结论，语义色和实物色继续承担原有职责。长表与复杂界面按任务裁取、重排或分步展开；为手机画幅重新设计层级。固定版面内的状态变化同样构成叙事推进，阅读停留按[防死帧](#防死帧)记录用途。

### 同一内容的两种编排

虚构任务：展示三份申请依次通过检查，观众需看清每份申请的身份、处理顺序和三个回执。

| 阶段 | kinetic 试排 | minimal 试排 | 共用证据 |
|---|---|---|---|
| 建立 | 三份带编号的申请进入同一处理空间 | 三行固定位置列出编号与待处理状态 | 三份输入可辨认 |
| 处理 | 当前申请沿路径进入检查窗口，窗口接力成为对应回执 | 当前行更新检查项与状态，完成后保留结果 | 同一编号从输入对应到回执 |
| 收束 | 拉远看齐三个回执，再稳定停留 | 三行完成态及总数同屏停留 | 三个结果、总数和读时一致 |

试排比较保持文案、事实和结果一致，调整动作幅度、构图变化及注意力交接。风格内的安静段与重点段共享同一视觉体系；具体效果在本片绘制中安排，运行时继续使用本片固定主题。

## 品牌黄色彩系统

当前内置主题的 `palette.accent` 使用 #FFC712。品牌黄承担当前焦点、关键路径或结果；数据、风险与实物原色各自保留真实含义。每片先固定颜色职责和主要关系，再以面积、明度、背景切换发展节奏。

| 关系 | 起始色组 | 使用方式 |
|---|---|---|
| 明暗组织 | #FFC712、深墨 #101116、暖白 #F5F5F7 | 深底上黄作焦点；黄底上用深墨文字；暖白用于留白和阅读 |
| 冷暖撞色 | #FFC712、蓝紫 #5B3DF5、深底 #05060A | 黄色负责主焦点，蓝紫区分另一组或空间层；蓝紫底文字用白色 |
| 近似色层次 | #FFC712、橙黄 #FF9F1C、浅黄 #FFE58A | 用明度、面积和深色轮廓区分层次，适合连续过程和较克制段落 |

这些色组是设计候选，采用的颜色在本片绘制中明确设置；主题 token 的实际默认值见文件开头的预设表。自绘镜头从 `context.theme.palette` 读取品牌色；`context.palette` 沿用 `spec.style.palette` 指定的绘画调色板。先在相同主体、文字和背景中做相邻色对照，再检查动态换色和编码结果。大色块变化绑定章节、状态或重点揭示；同一变量跨镜沿用颜色和标签。每镜可从中性色加一主一辅试排，强度通过面积与节奏调整。

按当前 `contrast()` 计算，#FFC712 与 #101116 约 12.06:1，白与 #5B3DF5 约 6.12:1；白与品牌黄约 1.56:1，黄色与蓝紫约 3.91:1。黄底采用深墨正文，蓝紫底采用白色正文。项目把正文／字幕对比度至少 4.5:1 作为设计检查起点，主题默认正文与背景继续满足校验器的 7:1；最终取样同时检查实际背景、透明混合、描边、字号和 360px 宽阅读。亮暗快速交替需检查闪烁风险；优先连续面积迁移和单次揭幕。公开依据见根 README.md 的可读性参考。

## 竖屏 9:16 口播版面默认
适用于 1080×1920 竖屏口播/解说短视频（其他尺寸按高度换算），常量在 `src/themes/shared.ts` 的 `VERTICAL_SHORT_LAYOUT`。
- 字幕贴底：字形下沿约 y=1580（距底 340，避开平台标题与账号名），渲染时 `captions.bottomInset` 取 `VERTICAL_SHORT_CAPTION_INSET`（≈0.177）。字幕可低于非字幕安全区的下边界 520。
- 屏幕大字基线约 1330；大字下沿与字幕上沿至少相隔 128。用 `bigTextBaselineFor(字幕上沿, 大字下伸, 推镜造成的最大下移)` 按实测字形计算，较近时整体上移，不压缩间距。
- 主视觉中心约 y=1000，主体与大字组成的视觉组围绕它排版；水平仍按画布中心 x=540。
- 验证：每镜头抽一帧，核对字幕下沿、大字与字幕间距和安全区；推镜最大倍数帧单独核对。

## 账号默认与每片风格选择
`.skill/brand.json` 保存**账号默认风格**（当前 `minimal`）。每片在初始化前取得主题选择：用户已指定主题或明确委托本片主题选择时，记录并执行；其余情形先询问用户，以 `minimal` 为默认推荐，结合本片任务说明 `kinetic` 备选的效果。默认推荐经用户答复或明确委托后采用。任务表帮助解释两种编排，最终主题按本片选择固定。

主题确定后，显式传入所选值创建项目，再按[沟通原文](workspace.md#沟通原文)补齐问答。`minimal` 与 `kinetic` 二选一替换下面的占位参数：

```bash
node .skill/scripts/video.mjs start <slug> --idea "用户原文" --theme <minimal|kinetic>
```

start 把账号默认与本片选择一起写进该片根目录的 `brand.json` 快照：`theme` 是本片生效风格，`defaultTheme` 是创建时的账号默认，`changes` 末尾记录日期及“显式指定主题”或“继承账号默认”的初始化事实。`workspace.json.brand` 记录同一选择与快照哈希，运行时核对快照未被改动（不一致报 `RUNTIME_BRAND_CHANGED`）。校验与渲染始终读这份固定快照。

主题选择的原文依据保存在 `prompt-history.jsonl`；快照中的自动记录用于标识采用值。`needs-intake` 表示继续处理剩余创作选择，已确认主题继续沿用。当前入口支持在初始化时选择主题；已有影片请求更换主题时，先说明固定快照约束，明确迁移范围、授权与验证方案，实施时保留原版本及其证据。

单片 spec 写了与 `theme` 不同的 `style.theme`：`enforcement: "override"` 时强制改回并给出 `BRAND_THEME_LOCKED` 警告，`"reject"` 时直接失败。更换**账号默认**时才改 `.skill/brand.json` 的 `theme`/`defaultTheme` 并在 `changes` 末尾追加记录（品牌级变更，只影响之后的新片）；已有影片保持各自的固定快照。version 1 的旧配置（`lockedTheme`）继续可读，按生效风格归一化。

## 防死帧
- `liveness` 是主题预设的微运动参数；校验器核对该预设轨迹的窗口位移。`theme_stage` 自动应用推镜、漂移与质感层，这些变化作为氛围单独记录。实际信息推进依据对象、关系和结果的变化验证。
- **信息/代码镜头**：按口播关键词分拍显现、点亮、拆解或对照，推进强度服从内容；阅读、观察或情绪停留登记明确用途。空档先检查叙事和读时，主体动作承担需要发生的信息变化。细则见[信息卡与清单分拍](motion-design.md#信息卡与清单分拍)。
- **稳定阅读**：自绘图解需要固定坐标时采用带有效 `composition` 的 `motion_stage`、`cameraMove: "static"`，并省略该镜的 `cameraPath`；存在 `cameraPath` 时管线优先采用该路径。本片绘制负责主体与相机时序；`theme_stage` 继续作为带微运动的标题预设。阅读停留、结果展示、反应和片尾身份均可保持静止，并记录起止时间与用途。
- 生成片段按内容选择变速和镜长，见[生成视频分层合成](assets.md#生成视频分层合成)。正反往复仅用于已验证可逆的循环动作；受力过程、口型和操作演示保持事件方向。代码管线里实拍慢放建议不低于约 0.6×；时长不足时优先换未用区间、补充素材或调整镜长。
- 审片：`node .skill/scripts/video.mjs <slug> exec node .engine/scripts/dead-frame-qa.ts out/final.mp4 [--json]`，比较相隔 0.5s 的帧（灰度、块平均、扣除颗粒噪声底），报告无可见变化的区间；有死帧退出码 2。连续静止 >1s 的区间写入本片 NOTES，并注明是否为上述允许例外。

## 个人 IP 使用规则
- IP 是小幅美术，**不当主视觉放大**。生成视频里的角色同样不放大超过源像素，见[生成视频分层合成](assets.md#生成视频分层合成)。显示边长 ≤ 源尺寸 512px（rig 头/身部件），推荐 256–384；超过即 `IP_UPSCALE` 校验失败（按实际输出像素换算，4K 输出同样受限）。
- `scenes[].ip` 默认不出现。只在两种情况使用：
  - `role: "identity"`：身份声明或需要时，例如片尾小签名（默认 288px，底部居中）。
  - `role: "actor"`：讲解动画中的演员，例如骑车、操作电脑（默认 384px）。
- 写法：`"ip": { "role": "identity", "size": 288, "position": "bottom-center", "expression": "happy" }`；`position` 可选 `bottom-center | bottom-left | bottom-right | center | custom`（custom 需 `x`、`y`，0–1，y 为角色底边）。旧写法 `ip: true` 自动降级为 288px 身份署名并告警。
- 纯文字镜头不放 IP，标题居中；身份署名在底部时标题略上移。

## 渲染前自检
出片前逐项过一遍，并在抽帧（每镜头一张 + 片尾）上实测：
- **主体居中**：采用居中构图时，按画布中心（竖屏 x=540、横屏 x=960）排版；偏置构图在镜头计划中注明焦点与用途。推/拉镜围绕已选焦点，安全区用于内容边界检查。居中构图实测：`node .skill/scripts/video.mjs <slug> exec node .engine/scripts/centering-qa.ts <still.png>... [--exclude x,y,w,h]`，内容包围盒中心水平偏移 ≤ 2%（角落署名用 `--exclude` 排除）；代码里用 `measureContentCenter` / `isCentered` / `withinSafeArea`（`src/qa/centering.ts`）。
- **安全区**：推镜到最大倍数时，文字和主体仍完整落在安全区内（竖屏 上220 / 下520 / 左72 / 右168）。
- **防死帧**：`dead-frame-qa.ts` 的候选区间逐段核对；有意阅读与情绪停留记录时间和用途，其余停滞按事件设计修正。
- **文字**：字形正确，各项文字按对应语义时点进入，完整结果保留读时；新旧文字交接清楚。
