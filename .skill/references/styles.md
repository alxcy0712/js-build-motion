# 风格选择

表中列出当前引擎已注册的主题预设。每片的视觉设计与效果组合按共用标准确定；新增内置主题需同步注册、品牌配置和校验。

| theme | 名称 | 关键 token | 适用 |
|---|---|---|---|
| `minimal`（默认） | 极简 | 底 #000、字 #F5F5F7、品牌黄 #FFC712；Inter + Noto Sans CJK SC；竖屏 hero 132；文字弹簧 k100 c25（零过冲）；进场 0.9s、holdMin 1.2s | 机制解释、证据对照、观点表达、品牌片尾 |
| `kinetic` | 动感 | 底 #05060A、品牌黄 #FFC712、默认第二色蓝紫 #5B3DF5；Inter Tight + Noto Sans CJK SC；竖屏 hero 168；文字进场 k380 c28（过冲 ≤4%）；进场 0.45s、holdMin 0.6s | 状态变化、操作结果、效率对比、产品与机制揭示 |

| 运行时预设参数 | minimal | kinetic |
|---|---|---|
| 可选推镜 `treatments.drift` | `scaleTo: 1.03, seconds: 5` | `scaleTo: 1.06, seconds: 3` |
| 颗粒 `treatments.grain` | `opacity: 0.03, fps: 24` | `opacity: 0.04, fps: 30` |
| 暗角 `treatments.vignette` | 0.55 | 0.6 |
| 辉光 `treatments.glow` | `blur: 120, opacity: 0.3`，目标 accent / subject | `blur: 60, opacity: 0.6`，目标 accent / text |
| 常规转场 `durations.transition` | 0.7s | 0.4s |
| 甩切 `durations.whip` | 沿用常规转场参数；默认转场列表采用其他类型 | 0.35s；当前管线将 whipPan / glitchCut 的实际时长上限设为 0.3s |
| 节拍 `bpm` | 96 | 128 |

参数权威来源为运行时的 `src/themes/styles/minimal.ts`、`src/themes/styles/kinetic.ts`；转场时长还经过 `src/pipeline/theme-transitions.ts` 计算，微运动轨迹由 `src/themes/liveness.ts` 求值。`scaleTo` 与 `seconds` 定义缓动推进的尺度和时间参数，实际逐帧值按该轨迹计算。表格随代码更新；采用值和当前编码的实际效果分别记录。

本片可用 `style: { "theme": "kinetic", "vignette": 0 }` 关闭暗角，或在 0–1 内调低强度；省略 `vignette` 时使用表中默认值。颗粒继续按主题参数绘制。暗角开启时在最终 RGBA8 合成上加入确定性的 ±1 色阶中性噪声，分散深色渐变的量化色带。

字幕与主题中文统一使用随运行时保存的 Noto Sans CJK SC；Inter、Inter Tight 与 Geist Mono 同样采用内嵌原版文件。恢复来源与摘要见根 README 的字体归因。缺少主题字体时渲染报 `FONT_NOT_FOUND`；`run.json` 的 `facts.fonts` 保存注册文件与完整 SHA-256，`facts.fontUsage` 保存实际文字绘制命中的 Skia 字族。

主题转场列表提供默认推荐。validate 按最终生效主题对推荐外的已登记转场给出 `THEME_TRANSITION_NOT_RECOMMENDED` 警告，并保留显式选择；渲染使用该选择，按语义、连续性与读时验收。未知 ID 及无效输入继续经过 VideoSpec 枚举校验与修复。`riseFade` 前半段淡出旧层、后半段淡入新层，共享切点的无字空档最多一帧；位移保留旧层上移 1.5%、新层从下方 3% 升起。

字号、停留、BPM 和转场列表提供预设起点。镜长按实测台词、动作与读时决定，主体和关系承担讲解；各类风格的强度选择和共同验收按[动效语言与制作标准](motion-language.md)。

所有风格共用必要信息安全区：竖屏 上220 / 下520 / 左72 / 右168；横屏 上72 / 下96 / 左右120。必要标签、来源和屏幕文字按安全区避让，字幕使用自己的版面。场景覆盖完整画幅，主体按镜头焦点与关系选择尺度，关键地标和动作空间保留可见；分层方法见[竖屏构图](vertical-framing.md#分开三层坐标)。

## 规则的作用范围

个人识别以[个人视频包装规范](visual-identity.md)为权威，本片沿用固定主题和已确认选择。模型可根据内容独立设计主体、场景、关系、材质、镜头编排和轨迹，并按[本片绘制](drawing.md)选择内置图元、组件副本、自绘或已验证的预渲染路径；各路径共用事实、识别、可读性与连续性验收。

| 类别 | 执行依据 | 验收 |
|---|---|---|
| 内容与正确性要求 | 事实、变量身份、品牌识别、完整读时、字幕可读性与本片已确认选择 | 在当前编码核对对象、因果、最后一项结果与手机阅读；本片固定主题继续按快照执行 |
| 风格默认 | 当前主题色板、字体、文字层级与进退场、字幕版面、包装结构和图形弹簧 | 沿用现有个人风格；minimal 保持精确克制与稳定阅读，kinetic 加强关键状态变化并安排稳定证据段 |
| 可调偏好 | 转场推荐、字号、进入时长、holdMin、BPM、微运动与镜头幅度 | 在个人识别与已确认选择内按内容、实测声音和样片调整；采用值、消费者及可见效果分别记录 |
| 技术硬限制 | 已登记枚举、有效数值范围、字体可用、固定时间与种子、运行时身份和编码条件 | 规格／运行时校验及适用回归；工程检查与视听验收分别保存证据 |

沿用默认时直接执行；内容适配的参数调整在现有 NOTES.md／events.md 记录依据与验证。涉及个人识别体系、固定主题或已确认方案的变更，按用户当次指派与已有授权处理，保留明确要求的选择与审批。方法表、效果清单和示例数值作为可改写的起点，具体实现由模型在本片契约内决定。

`durations.enter` 在通用 theme-stage 的首屏处理处消费；`revealState` 的实际文字轨迹使用 `textReveal`，自绘镜头按自己的调用执行。`holdMin`、主题 `bpm` 与 `maxCharsPerScreen` 提供设计起点；镜长、节拍和字数检查以各自实际消费者及本片读时为准。

文字过冲由 `textReveal` 与 `springs.text` 的校验和钳制管理：minimal 为零过冲，kinetic 上限为 4%。必要文字按最大入场尺度与字形外框预留空间，核对完整动画期间的边界。`layout`、`accent`、容器边缘和相机分别按材质与语义选择参数；数据值、刚性尺寸与品牌路径保持内容约束。持续对象的标签沿用同一状态与锚点，新增文字在取得阅读空间后进入，字幕保持屏幕坐标；同类文字的运动语法在实际交接处统一。

`treatments.motionBlur` 当前由 `whipPan` 消费，在固定旧／新离屏画面上多次采样归一化位移。普通镜内对象、相机和文字使用当前时刻求值。快速动作先按[跨镜连续状态](motion-design.md#跨镜连续状态)修正轨迹，再比较原生帧率与局部时间采样；配置值、实际调用和编码效果各自核验。

## 按任务选择表现方式

先确定观众要辨认的对象、需要看清的变化和最后要记住的结果，再提出风格方案。本节描述当前两种主题的创作取向；每片主题沿用下文的选择与快照规则。网站标签、作品标题和明暗配色分别提供检索线索，采用时按实际信息任务判断。

| 内容任务 | kinetic 的组织方式 | minimal 的组织方式 | 选择依据 |
|---|---|---|---|
| 产品发布、功能亮点 | 用一次操作带出结果，在关键发现处放大尺度与颜色反差 | 保留真实界面骨架，聚焦输入、反馈和完成状态 | 核心卖点能由短动作证明时适合 kinetic；操作细节需要逐步辨认时适合 minimal |
| 机制、教程、技术流程 | 用对象沿路径传递、聚合或分解揭示关键机制 | 固定空间、坐标和标签，按因果逐步更新局部 | 需要记住变化方向时采用较强动作；需要追踪多个变量时优先稳定布局 |
| 跑分、数据、证据比较 | 揭示差异时集中强调，随后落定到完整对照 | 保持基线、单位、列宽和比较条件，依次指出差异 | 证据阅读段保留稳定参照；效果强度随数据密度降低 |
| 品牌、身份、情绪收束 | 内容母题回归，主动作完成后形成明确落点 | 通过留白、字重和精确对齐收束注意力 | 结尾的身份、结论和必要署名各有读时 |

### kinetic：用变化建立记忆点

1. **建立对象**：先让观众认出一个具体对象、操作或问题，给贯穿母题指定身份和作用。轮廓、颜色、位置或路径承担接力线索。
2. **证明变化**：一次主要动作承载一个可核对的结果。用形状接力、前后景尺度差、局部放大或文字重组突出本段动词；文字的形变对应压缩、分组、展开等含义。
3. **安排强弱**：普通段落用较少层次，关键发现集中投入形变、换色或运镜。音乐段按实测重音安排触发、峰值与落定，阅读段以读完为界。
4. **回到结果**：动作收束后，主体、完整数值和单位清楚呈现，再把结果交给下一镜。母题回归时带回已经发生的变化。

将大字、背景变化、相机加速分配到不同的注意力交接时点。装饰层在证据进入时降低权重。图表数据、品牌轮廓与刚性部件保持各自的约束；夸张集中在允许变化的图形层。短展演的逐拍换形适合展示运动技巧，知识解释的节奏由因果与读时决定。

### minimal：用稳定参照显现差异

1. **建立参照**：固定主体框架、图表坐标或对照列，先交代对象身份、输入条件和单位。留白将当前问题与辅助信息分开。
2. **局部推进**：一次操作更新相关字段、路径或部件，其他参照继续可见；前一步结果保留为下一步的依据。
3. **展示证据**：把标签、数值和图形绑定到同一状态。比较使用相同刻度、单位、精度与对齐方式，完整结果出现后开始计算读时。
4. **形成结论**：用局部强调或精简结论指出变化，保持清晰、稳定的结果画面。需要看细节时局部放大，随后回到原有空间。

质感来自比例、字重、间距、边缘与时序的精确配合。品牌黄集中指向当前变量或结论，语义色和实物色继续承担原有职责。证据截图按原比例完整呈现，用绑定原件坐标的划线、圈框和聚焦引导阅读；长表可分步解释并保留全貌参照。固定版面内的状态变化同样构成叙事推进，阅读停留按[防死帧](#防死帧)记录用途。

### 同一内容的两种编排

虚构任务：展示三份申请依次通过检查，观众需看清每份申请的身份、处理顺序和三个回执。

| 阶段 | kinetic 试排 | minimal 试排 | 共用证据 |
|---|---|---|---|
| 建立 | 三份带编号的申请进入同一处理空间 | 三行固定位置列出编号与待处理状态 | 三份输入可辨认 |
| 处理 | 当前申请沿路径进入检查窗口，窗口接力成为对应回执 | 当前行更新检查项与状态，完成后保留结果 | 同一编号从输入对应到回执 |
| 收束 | 拉远看齐三个回执，再稳定停留 | 三行完成态及总数同屏停留 | 三个结果、总数和读时一致 |

试排比较保持文案、事实和结果一致，调整动作幅度、构图变化及注意力交接。风格内的安静段与重点段共享同一视觉体系；具体效果在本片绘制中安排，运行时继续使用本片固定主题。

## 品牌黄色彩系统

minimal 与 kinetic 共用主色 **#FFC712**（`palette.accent`），默认第二色为蓝紫 **#5B3DF5**（`palette.accent2`）。第二色提供可直接采用的配色起点；其他辅助色可按题材、素材、数据类别和情绪需要选择，并在本片记录用途。主色身份贯穿整片，画面面积由叙事层级决定。

### 颜色职责

| 职责 | 起点 | 设计用法 |
|---|---|---|
| 主色／品牌识别 | #FFC712 | 当前对象、关键路径、结论与身份回归；同一镜头建立一个主要注意目标 |
| 默认第二色 | #5B3DF5 | 第二组对象、背景空间、过程容器或相邻章节；通过位置、面积与主色建立层级 |
| 按内容选择的辅助色 | 蓝、青、绿、橙、粉等经过验证的颜色 | 补足分类、材质、情绪和场景关系；每种新增颜色对应一个可说明的作用 |
| 中性色 | 深墨 #101116、暖白 #F5F5F7、灰阶 | 承载阅读、留白、坐标和辅助标签，给主次颜色留出辨认空间 |
| 语义色与实物色 | 数据约定、风险提示、真实品牌与产品颜色 | 保持既有含义与真实识别；同时用标签、形状或位置解释区别 |

颜色表先写“对象／变量 → 角色 → 色值 → 明暗背景上的文字色”，再设计镜头。同一对象跨镜沿用身份；状态改变时，通过标签与动作说明换色原因。辅助色数量由可辨认的类别和层次决定，进入证据阅读阶段后降低装饰层的饱和度、面积或透明度。

| 关系 | 起始色组 | 使用方式 |
|---|---|---|
| 明暗组织 | #FFC712、深墨 #101116、暖白 #F5F5F7 | 深底上黄作焦点；黄底上用深墨文字；暖白用于留白和阅读 |
| 冷暖撞色 | #FFC712、蓝紫 #5B3DF5、深底 #05060A | 黄色负责主焦点，蓝紫区分另一组或空间层；蓝紫底文字用白色 |
| 近似色层次 | #FFC712、橙黄 #FF9F1C、浅黄 #FFE58A | 用明度、面积和深色轮廓区分层次，适合连续过程和较克制段落 |
| 自然与技术内容 | #FFC712、深青 #146B68、暖白 #F5F5F7 | 深青承载环境或第二类对象，黄用于当前步骤；适合自然过程、设备状态与信息路径 |
| 多类证据 | 品牌黄加按类别选定的辅助色 | 每类保留固定标签、标记形状与图例；比较镜头继续使用相同映射 |

这些色组是设计候选，采用的颜色在本片绘制中明确设置；主题 token 的实际默认值见文件开头的预设表。自绘镜头从 `context.theme.palette` 读取主色和默认第二色；本片 `src/` 可定义有内容依据的辅助色。`context.palette` 沿用 `spec.style.palette` 指定的绘画调色板，该字段继续使用已登记的调色板 ID。每镜可从中性色加一主一辅试排，按任务增加必要的类别色；强度通过面积、饱和度和节奏调整。

### 按设计范本展开

沿用[设计学习](design-learning.md#先约定要发生的体验)中的“目的 → 关系 → 编排 → 验证”步骤。下面是可改写的虚构设计范本；本片根据内容选择对象、构图与辅助色，并用完整动态粗剪验证。

| 范本与信息任务 | minimal 的实现 | kinetic 的实现 | 验收重点 |
|---|---|---|---|
| 产品功能：一次操作获得结果 | 深底保留真实界面，黄框定位当前操作；默认蓝紫或按产品内容选定的辅助色标记处理区域 | 先呈现实物或界面，再让黄色操作点触发容器展开；第二色承接过程空间，落定后显示结果 | 产品识别准确；操作、反馈、结果对应；高亮清楚且正文可读 |
| 机制流程：三份输入合成一个输出 | 固定节点与标签，黄色依次沿路径推进；不同输入用稳定的类别色和形状区分 | 输入保持颜色身份汇聚，第二色容器展开为解释窗口；黄色最终指向共同输出 | 输入数量与身份可追踪；转换前后因果清楚；结果有完整读时 |
| 数据比较：同条件的两组结果 | 固定尺度、单位与对齐，黄指向当前重点，第二色表示另一组；其他类别按图例增加辅助色 | 用面积或尺度变化揭示差异，随后落定到相同基线的完整对照；镜头切换沿用颜色映射 | 相同数值对应相同几何；图例、数值和图形一致；辅色与标签可区分 |
| 情绪与身份：过程结束后留下结论 | 暖白或深墨留白，黄用于结论或小幅身份标记；环境与人物保留自身颜色 | 内容母题回归，第二色空间收束，黄色成为最后的明确落点；动作完成后稳定停留 | 品牌黄可识别；身份、结论与必要署名各有读时；主次关系稳定 |

minimal 通过稳定构图、有限高亮面积和局部更新组织颜色；kinetic 通过较明显的面积迁移、空间接力与强弱变化组织颜色。两者都允许按内容选用其他辅助色。大色块或背景换色绑定章节、状态或关键揭示，换色期间维持对象身份与文字对比度。

### 配色验证

先在相同主体、文字和背景中比较默认蓝紫与本片候选辅助色，保留选择依据。检查静帧中的主次层级，再连续观看重点动作和换色过渡；在 360px 宽画面核对文字、图例与主体，必要时用灰度检查不同类别是否还能靠标签与形状辨认。最终颜色判断以编码后的画面为准，辉光、颗粒、半透明与背景变化均纳入取样。

按当前 `contrast()` 计算，#FFC712 与 #101116 约 12.06:1，白与 #5B3DF5 约 6.12:1；白与品牌黄约 1.56:1，黄色与蓝紫约 3.91:1。黄底采用深墨正文，蓝紫底采用白色正文。项目把正文／字幕对比度至少 4.5:1 作为设计检查起点，主题默认正文与背景继续满足校验器的 7:1；最终取样同时检查实际背景、透明混合、描边、字号和 360px 宽阅读。亮暗快速交替需检查闪烁风险；优先连续面积迁移和单次揭幕。公开依据见根 README.md 的可读性参考。

## 竖屏 9:16 口播版面默认
适用于 1080×1920 竖屏口播/解说短视频（其他尺寸按高度换算），常量在 `src/themes/shared.ts` 的 `VERTICAL_SHORT_LAYOUT`。
- 字幕中轴线：外框中轴线位于 75%–80% 屏高，默认 77.5%；单行、多行和双语共用该轴，实际字形在框内上下居中。省略 `captions.bottomInset` 使用此默认，显式值用于本片确认的位置覆盖。字幕可低于非字幕安全区的下边界 520，完整字幕框需在当前平台预览中避开底部信息和右侧互动按钮。几何、双语与普通字幕叠加见[字幕外框与底部](captions-and-shots.md#字幕外框与底部)。
- 屏幕大字基线约 1330；大字下沿与字幕上沿至少相隔 128。用 `bigTextBaselineFor(字幕上沿, 大字下伸, 推镜造成的最大下移)` 按实测字形计算，较近时整体上移，不压缩间距。
- 主视觉中心约 y=1000，主体与大字组成的视觉组围绕它排版；水平仍按画布中心 x=540。
- 验证：每镜头抽一帧，实测外框高、中轴线位置、字形上下留白、大字间距和平台界面避让；固定内容的底部跨时间保持同一颜色，推镜最大倍数帧单独核对。

## 账号默认与每片风格选择
`.skill/brand.json` 保存**账号默认风格**（当前 `minimal`）。每片在初始化前取得主题选择：用户已指定主题或明确委托本片主题选择时，记录并执行；其余情形先询问用户，以 `minimal` 为默认推荐，结合本片任务说明 `kinetic` 备选的效果。默认推荐经用户答复或明确委托后采用。任务表帮助解释两种编排，最终主题按本片选择固定。

主题确定后，显式传入所选值创建项目，再按[沟通原文](workspace.md#沟通原文)补齐问答。`minimal` 与 `kinetic` 二选一替换下面的占位参数：

```bash
node .skill/scripts/video.mjs start <slug> --idea "用户原文" --theme <minimal|kinetic>
```

start 要求显式传入 `--theme`；缺失时报 `THEME_REQUIRED`，在创建项目与备份之前停止。账号推荐值也通过这一参数采用。start 把账号默认与本片选择一起写进该片根目录的 `brand.json` 快照：`theme` 是本片生效风格，`defaultTheme` 是创建时的账号默认，`changes` 末尾记录日期及“显式指定主题”的初始化事实。`workspace.json.brand` 记录同一选择与快照哈希，运行时核对快照未被改动（不一致报 `RUNTIME_BRAND_CHANGED`）。本片 `.engine` 的校验与渲染始终读这份固定快照。

直接调用核心 `validateSpec` 时，显式的 `style.theme` 按规格保留；需要固定手建项目的主题时，传入 `{ brand: loadBrand(本片brand路径) }`。核心账号配置仅参与新片初始化。Linux 手建工作区与命令边界按根 AGENTS.md 的对应流程执行。

主题选择的原文依据保存在 `prompt-history.jsonl`；快照中的自动记录用于标识采用值。`needs-intake` 表示继续处理剩余创作选择，已确认主题继续沿用。当前入口支持在初始化时选择主题；已有影片请求更换主题时，先说明固定快照约束，明确迁移范围、授权与验证方案，实施时保留原版本及其证据。

单片 spec 写了与 `theme` 不同的 `style.theme`：`enforcement: "override"` 时强制改回并给出 `BRAND_THEME_LOCKED` 警告，`"reject"` 时直接失败。更换**账号默认**时才改 `.skill/brand.json` 的 `theme`/`defaultTheme` 并在 `changes` 末尾追加记录（品牌级变更，只影响之后的新片）；已有影片保持各自的固定快照。version 1 的旧配置（`lockedTheme`）继续可读，按生效风格归一化。

## 防死帧
稳定阅读、主体信息变化与氛围运动分别检查。静止指标定位候选区间，阅读与情绪停留按用途验收；微运动的参数检查覆盖所选轨迹，信息推进按对象和关系的实际变化验证。

- **本地实拍剪辑**：本地剪辑软件按素材动作、镜头节奏与剪辑习惯处理停留，`microMotionAt` 属于代码镜头的可选实现工具。该函数在本地实拍剪辑流程中免于强制调用；有意静止的用途与实际观测范围写入审片记录。
- `liveness` 提供可选氛围运动的预设轨迹，校验器验证其参数与窗口位移。`theme_stage` 在显式动态 cameraMove 且省略 cameraPath 时采用主题微运动；静镜保持固定相机与背景坐标，显式 cameraPath 独立控制相机。颗粒作用于完整场景；minimal 与 kinetic 默认不使用扫光（用户认为扫光碍眼）。字幕按[普通叠加层](captions-and-shots.md#字幕外框与底部)绘制。实际信息推进依据对象、关系和结果的变化验证。
- **信息/代码镜头**：按口播关键词分拍显现、点亮、拆解或对照，推进强度服从内容；阅读、观察或情绪停留登记明确用途。空档先检查叙事和读时，主体动作承担需要发生的信息变化。细则见[信息卡与清单分拍](motion-design.md#信息卡与清单分拍)。
- **稳定阅读**：`motion_stage` 与 `theme_stage` 均可采用 `cameraMove: "static"` 并省略 `cameraPath`；存在 `cameraPath` 时管线优先采用该路径。本片绘制保持页面、证据和标注的共同坐标，按语义安排进场、划线和重点切换。阅读停留、结果展示、反应和片尾身份可保持静止，记录起止时间与用途。静止候选通过读时与信息用途验收，循环漂移按明确的内容需要采用。
- 生成片段按内容选择变速和镜长，见[生成视频分层合成](assets.md#生成视频分层合成)。正反往复仅用于已验证可逆的循环动作；受力过程、口型和操作演示保持事件方向。代码管线里实拍慢放建议不低于约 0.6×；时长不足时优先换未用区间、补充素材或调整镜长。
- 审片：`node .skill/scripts/video.mjs <slug> exec node .engine/scripts/dead-frame-qa.ts out/final.mp4 [--json]`，比较相隔 0.5s 的帧（灰度、块平均、扣除颗粒噪声底），报告无可见变化的候选区间；有候选时退出码 2。连续静止 >1s 的区间写入本片 NOTES，标明阅读、结果、观察或情绪用途；其余停滞按事件设计修正。

## 个人 IP 使用规则
- IP 是小幅美术，**不当主视觉放大**。生成视频里的角色同样不放大超过源像素，见[生成视频分层合成](assets.md#生成视频分层合成)。显示边长 ≤ 源尺寸 512px（rig 头/身部件），推荐 256–384；超过即 `IP_UPSCALE` 校验失败（按实际输出像素换算，4K 输出同样受限）。
- `scenes[].ip` 默认不出现。只在两种情况使用：
  - `role: "identity"`：身份声明或需要时，例如片尾小签名（默认 288px，底部居中）。
  - `role: "actor"`：讲解动画中的演员，例如骑车、操作电脑（默认 384px）。
- 写法：`"ip": { "role": "identity", "size": 288, "position": "bottom-center", "expression": "happy" }`；`position` 可选 `bottom-center | bottom-left | bottom-right | center | custom`（custom 需 `x`、`y`，0–1，y 为角色底边）。旧写法 `ip: true` 自动降级为 288px 身份署名并告警。
- 纯文字镜头不放 IP，标题居中；身份署名在底部时标题略上移。
- 片尾头像与个人 IP 落款是经用户确认后采用的专用身份版式，与收尾口播「我是澄记，用计算机思维想现实。」同时采用或同时省略：头像居中、显示边长约 400px（仍不超过 512），规格见[片尾头像与个人 IP 落款](visual-identity.md#片尾头像与个人-ip-落款)。

## 渲染前自检
出片前逐项过一遍，并在抽帧（每镜头一张 + 片尾）上实测：
- **主体居中**：采用居中构图时，按画布中心（竖屏 x=540、横屏 x=960）排版；偏置构图在镜头计划中注明焦点与用途。推/拉镜围绕已选焦点，安全区用于内容边界检查。居中构图实测：`node .skill/scripts/video.mjs <slug> exec node .engine/scripts/centering-qa.ts <still.png>... [--exclude x,y,w,h]`，内容包围盒中心水平偏移 ≤ 2%（角落署名用 `--exclude` 排除）；代码里用 `measureContentCenter` / `isCentered` / `withinSafeArea`（`src/qa/centering.ts`）。
- **安全区与画幅**：推镜到最大倍数时，必要文字与标签保持平台避让，关键地标和关系仍可见；主体尺度与环境覆盖按[三层坐标](vertical-framing.md#分开三层坐标)检查。字幕单独核对外框、读时与界面避让。
- **防死帧**：`dead-frame-qa.ts` 的候选区间逐段核对；有意阅读与情绪停留记录时间和用途，其余停滞按事件设计修正。
- **文字**：字形正确，各项文字按对应语义时点进入，完整结果保留读时；新旧文字交接清楚。
