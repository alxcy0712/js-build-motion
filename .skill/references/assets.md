# 素材选择与生图

按镜头目的选择素材。复杂实物、环境、材质和插画优先评估生图；品牌、文字、数据和技术关系优先采用可核对的精确图形。同一镜头可组合生成图片、官方矢量与代码动画。用户明确的纯代码或素材要求优先。

## 本轮能力事实

先检查当前会话实际可调用的生图接口或已授权服务，记录接口、可用状态和能力范围。工具注册表的adopted表示工作流支持；本轮调用能力依据当前接口与实际结果。可用时通过对应工具生成素材；工具缺席、调用失败或结果经修订仍未满足本片用途时，记录原因并转用代码、SVG、Canvas或可验证的三维路径。付费、访问与服务变更沿用用户授权。

imagegen由agent在素材准备阶段调用，最终渲染读取已保存的图片。调用前读取当前宿主提供的对应工具规则。收到固定宿主路径的结果后，立即将本轮生成文件迁入本片assets/generated/，清理本轮可管理的源副本；工具管理的缓存按实际能力记录。全部候选图、修订图、提示词与检查证据归入本片，代码引用本片路径。

## 按用途组合

| 用途 | 优先实现 | 验收重点 |
|---|---|---|
| 复杂实物、环境、材质、叙事插画 | 根据真实资料与本片画风生图，准备构图余量与分层素材 | 主体身份、实物外观、透视、光照、同片一致性 |
| Logo、品牌标识、文字、数据图表 | 官方SVG、精确路径、代码文字与数据绘制 | 完整路径、比例、孔洞、文字与数值 |
| 工艺剖面、器件连接、过程演示 | 可靠资料约束的代码几何；生成图片可承担外围环境与材质 | 材料分隔、端子连接、方向、尺度、工序前后 |
| 空间结构、环绕、爆炸分层 | 评估本片三维方案，按[绘制](drawing.md)验证出片 | 几何、遮挡、相机、固定时间求值与编码结果 |

真实感与结构准确性分别验收，技术结构按[精确几何](reference-geometry.md)对照独立资料。先核对主体，再增加材质与光照；教学简化和视觉比喻明确标注。已确认的主体参考贯穿后续生成，维持比例、材料、视角与风格。

生成图进入视频时按需要拆分前景、主体和背景；准备透明层、遮罩或足够的裁切余量，结合推拉、视差、焦点转移与代码叠加动画。单张图片可承担有限平移和缩放；大幅换角度与环绕需要三维几何或经验证的多视角素材。先做代表性短样片检查融合、边缘、画面运动与字幕避让。

产品与结构图片按[位图裁切与量尺](reference-geometry.md#位图裁切尺度与量尺)核对源裁框、等比缩放与测量口径；身份地标和阅读区留足裁切余量。外围纹理、主体结构与事实标注分别验收。

## 输入与声明

assets/reference/保存参考，assets/generated/保存生成图，assets/保存模型、纹理与授权输入；本轮检查和生成记录保存于evidence/，临时文件放out/.tmp/。按镜头在NOTES.md登记素材选择及用途，在evidence/assets.json登记提示词、实际工具或提供方、参考输入、生成或修订状态、项目内路径与SHA-256。

brief.assets列出实际素材、来源、使用口径与哈希。实际采用生图时tools.allowed加入imagegen，并设置pureCode=false、zeroExternalAssets=false；使用官方素材时按实际输入填写声明。工具准备、素材冻结与代码渲染分别记录，最终run.json与披露核对实际消费的文件。固定图片后的逐帧重现与再次调用生成服务的重现能力分别陈述。

## 镜头需求、版本选择与实际消费

已入库来源先登记 catalog，再用 `assets --schema plan` 建立本片 `assets/asset-plan.json`。AssetNeed 保存镜头、用途、动作/视角/身份需求、尺寸/时长/权利用途约束与替代方案；AssetUse 用稳定 useId 绑定 needId、shotId、角色、catalogId、目录清单哈希、assetId、assetVersion 与原件字节哈希。选择同时保存源区间、归一化裁框、contain/cover 和静音口径。`assets` 复查来源与派生证据，列出技术、权利、语义、构图和连续性缺口；人工审查继续绑定该镜头与固定版本。

新生产计划采用 0.2，视频 `mute` 缺省为 false，按相同 sourceRange 绑定保留原声的准备版本。历史 0.1 视频选择继续使用其明确静音口径。低清 proxy 用于预览和粗剪；正式消费绑定满足交付尺寸的 canonical，画质需求按实际选用像素复查。来源、交付帧与原声用固定块核验并进入输入快照。

0.2 照片绘制采用目录记录的源像素预算，与 OCR 识别预算各自校验；PNG/JPEG 保留原始尺寸用于正式绘制。当前受控素材准备共用 256 MiB 驻留预算，计入照片编码字节和解码像素；超额时保留原件，准备满足交付尺寸的派生图，或分段准备当前镜头所需素材。

```bash
node .skill/scripts/video.mjs <slug> assets --schema plan
node .skill/scripts/video.mjs <slug> assets --plan assets/asset-plan.json
node .skill/scripts/video.mjs <slug> render --asset-plan assets/asset-plan.json --no-network
```

render 默认读取已存在的 `assets/asset-plan.json`，冻结计划、原件、目录清单与选用的派生文件。异步准备通过 [prepareDrawing](drawing.md#受控素材准备) 加载 AssetPort，逐帧使用同步句柄；每次成功读取、图片绘制、帧访问和视频绘制生成消费回执，包含原件与实际选用文件身份、use/need/shot/角色以及帧号和源 PTS。回执文件绑定本次输入快照，run 与 artifact 复查这些关系。

AssetPort 的消费记录覆盖受控调用，动态 IO 与最终像素可见性保留 unknown。完整内置程序绘制与程序音频的闭合路径可报告该范围内零外部消费；已有自定义绘制与部分覆盖路径保留待核验。披露按精确路径和实际读取哈希对账，选用声明、消费证据与权利记录各自保存。视频准备、成功发布与恢复边界见 [有界视频准备](workspace.md#有界视频准备)。

## 生成视频分层合成

适用条件：用图生视频/文生视频为角色（个人 IP、演员）生成动作，再与代码画面合成。

- **分层**：生成片段只承担角色动作；背景为平涂纯色（灰或白，便于抠像），手机/电脑等设备屏幕保持空白，画面内不出现任何文字。大字、字幕、标签、气泡、按钮、章节卡和屏幕内容全部由代码绘制。生成提示词只写动作、平涂底色、空白屏幕与“no text, no logos”。分镜对每个生成镜头写“生成部分（纯动作）｜代码部分（文字/UI/光效）”一行。
- **参考图输入**：调用前确认当前生成工具可读取的参考路径。Grok Bot 的 GenerateVideo 读取不到 /workspace 下的文件或 URL，需先把参考图复制到该 bot 自己的素材目录再传入；其他工具按各自规则核验，失败时记录实际接口与原因。结果仍按上文迁入本片 assets/generated/。
- **抠像**：`node .skill/engine/scripts/key-footage.ts <clip.mp4> <outDir>` 输出透明帧序列与 meta.json（`--preset white` 用于白底，`--key #RRGGBB` 指定键色）。算法为边框连通的通道距离键 + 封闭平涂区判定 + 1px 收缩 + 羽化 + 去溢色（`src/footage/key.ts`），深色衣物不会因接近灰底被抠穿。阈值按素材在暗背景和亮背景上各目检一次边缘。
- **贴槽变速**：`openKeyedClip(dir, slot)` 把片段线性贴到镜头槽位，速率限定 0.75–1.5×；片段过长按 1.5× 截断，过短以 0.75× 播完后正反往复（pingpong），任何一帧源时间都在变化，不出现冻结帧。超出范围优先重新生成或调整镜长。
- **帧混合**：输出帧率高于源帧率（如 24→60fps）时默认混合相邻两帧（预乘，透明边缘不发暗），慢动作不再一顿一顿。
- **尺寸上限**：`drawCharacterLayer` 按当前变换（含推镜）计算屏幕缩放，1 个源像素至多占 1 个输出像素，角色永不放大超过源尺寸；要更大的角色就生成更高分辨率的片段。与个人 IP 尺寸规则一致，见[风格选择](styles.md#个人-ip-使用规则)。
- **黑底融合**：可选底部渐隐（`fadeBottom`）让半身角色落入背景；深色衣物在黑底上看不清时加低强度强调色轮廓光，alpha ≤ 0.15（`RIM_ALPHA_MAX`），只勾边不发光。

验证：抠像后抽首/中/尾帧在目标背景上检查边缘与封闭区；样片中以正常速度看变速段的连续性，`dead-frame-qa.ts` 无死帧；在推镜最大倍数的帧上核对 `drawCharacterLayer` 返回的 screenScale ≤ 1。
