# 个人视频包装规范

本文件固定跨片复用的识别规则、常用组件结构、选用方法与验收要求。新片从本文件生成 `guide/visual-identity.md` 快照，开工、分镜和审片均读取。完整选型见[视频剪辑元素目录](editing-element-catalogue.md)：17 类、154 项素材与组件，加 23 组处理方式；按当前内容选取足够完成表达的元素。

账号识别层保持颜色职责、文字层级、标注形态、容器结构和动作语法一致；每片表现层根据题材设计主体、场景、构图、材质与情绪节奏。用户当次要求和已确认选择决定本片范围，执行角色、素材权利与审批沿用仓库和本片约定。规范描述制作要求；可直接调用的组件以本片能力查询、组件目录和实际源码为准，具体画法与样片按下文记录实现状态。

## 固定识别规则

| 维度 | 跨片沿用的规则 | 每片落实与验证 |
|---|---|---|
| 品牌色 | 主色 #FFC712 指向当前焦点、关键路径或结论；默认第二色 #5B3DF5，其他辅助色按内容选用；主体实物色与数据语义色保持各自含义 | 读取固定主题的 `palette`，颜色职责、配色范本和对比检查按[品牌黄色彩系统](styles.md#品牌黄色彩系统)执行 |
| 识别母题 | 以黄色短线、框角或下划线标记“当前看这里”；人物条、资料卡和结论沿用同一笔画体系 | 标记绑定一个真实对象或关键词；引导线从对象连到解释，完成态落在结果上，同一时刻保留一个主要焦点 |
| 文字层级 | 标题／关键数字、解释正文、来源／辅助标签各有稳定层级；同主题跨片沿用字体、字重和层级职责 | 字体与字号从本片主题 token 起步，字幕按[短字幕规范](captions-and-shots.md)独立排程；实际字体、手机读时与长文本换行逐项检查 |
| 信息容器 | 人物条和资料卡采用整齐矩形、清楚边界与单侧黄色标记；主体信息优先，来源在独立辅助区 | 同一组件的边线、留白、对齐和文字层级共用一组样式；原始截图与品牌标识保留真实外观，明暗变体只调整承载层 |
| 动作语法 | 当前对象出现 → 重点被标记 → 结果落定 → 完整阅读 → 收束或交给下一镜 | 用本片主题的进入、退出与缓动参数；同类组件共用进入方向和退场逻辑，语义时点和完整读时按[共用动效标准](motion-language.md)验证 |
| 个人形象 | 需要创作者身份或本人参与讲解时，沿用已指定 IP 的身份特征与现有授权素材 | 素材复制到本片并登记来源；尺寸、位置和身份／演员角色按[个人 IP 使用规则](styles.md#个人-ip-使用规则)核对 |
| 声音 | 人声承担内容，环境声建立空间，短提示音对应进入、强调或完成事件；同类事件沿用选定的声音与强弱关系 | 沿用执行角色的配音授权；已确认声音标识按版本复用，其余音效按本片内容选择，实测与试听见[音视频流程](execution.md) |

`minimal` 与 `kinetic` 共用上述识别层，分别采用稳定参照和较强状态变化。每片主题继续按[账号默认与每片风格选择](styles.md#账号默认与每片风格选择)取得选择并固定；识别规则随主题调整动作强度，字段顺序和品牌色职责保持一致。

正片的容器和收尾从本片内容设计；`assets/douyin-cover/` 中的模板与版式保持独立封面用途。镜头间通过主体动作、景别、空间和证据组织变化，同类包装在需要时出现。每片特色以实际表达和记忆点检验，元素数量按信息需要确定。

## 常用组件及触发条件

下列 12 组作为优先复用的包装结构。触发条件成立时采用相应结构，用户已有约定优先；全部组件共用上面的识别规则。表中编号对应完整目录，组合组件可使用多个条目。

| 组件组 | 何时使用 | 固定结构与行为 | 目录编号 |
|---|---|---|---|
| 口播字幕 | 有口播、对白或必要声音信息 | 保持统一字号、描边或底板、基线及断句；强调词沿用品牌黄，人物条与引用卡避让字幕，字幕按实测声音切换 | E001–E003、E006 |
| 标题与关键词 | 建立问题、章节或强调核心词／数字 | 一处黄色短线或下划线配主标题；主副层级稳定，强调完成后保留清楚的完整信息 | E004、E009–E015 |
| 人物与情境条 | 人物首次出现、身份变化或必要时空交代 | 姓名／地点为主行，身份／时间为次行，单侧黄色短线；在安全区内靠近关联主体，解释完成后退出 | E016–E024 |
| 引用与资料卡 | 引用原话、文章、截图、帖子、录音或视频 | 标题区 → 原件／引文区 → 来源区；黄色框角标当前证据，逐步放大或划出相关句，作者、日期及必要口径随内容可读 | E025–E035 |
| 标注与局部放大 | 指出按钮、细节、路径或易漏信息 | 黄色圈框／下划线／引导线使用一致笔画；标注锚点跟随对象，放大窗保留原位置线索，解释结束后收束 | E036–E045 |
| 步骤与清单 | 讲操作顺序、规则、准备项或进度 | 编号、条目、状态分列；当前项用黄，已完成项保留可辨状态，最后一项完成后给整组读时 | E046–E053、E059 |
| 数字与图表 | 数据承担主张或结论 | 数值、单位、比较条件和来源形成完整一组；图形和数字由同一状态驱动，黄标当前值，落定后展示精确结果 | E054–E062、E071 |
| 对比板 | 比较前后状态、方案或不同证据 | 同基线、同单位、同维度对齐；对象身份固定，黄色只指当前讨论差异，比较条件始终可核对 | E032、E057、E084–E085、E102–E103 |
| 流程、关系与时间线 | 解释机制、因果、层级或发展顺序 | 同一对象保留编号和颜色；当前路径用黄，前一步结果交给下一步；空间或比例简化注明依据 | E063–E071 |
| 资料窗口与画中画 | 主画面需同步展示证据、演示或反应 | 统一容器边界、素材边距和说明区；证据截图按原比例完整展示，划线与聚焦绑定原件坐标，局部放大保留全貌参照；实景按镜头用途取景 | E083–E091 |
| 问题与结论卡 | 提问、揭晓或收束一段推理 | 问题指向具体对象，结论带回已经展示的证据；黄色标记从问题或过程落在结果，完整读时从结果形成开始 | E010、E014、E046、E049–E050 |
| 身份与收尾 | 本片需要账号身份、栏目识别或制作署名 | 沿用已确认名称、标识与 IP，结论和身份分清主次；必要素材署名完整保留，结尾先完成本片内容；片尾头像与个人 IP 落款按[片尾规格](#片尾头像与个人-ip-落款)，仅在用户确认后采用 | E092–E099、E112 |

收尾口播「我是澄记，用计算机思维想现实。」只与片尾头像与个人 IP 落款一起使用：用户确认采用时，两端都按[片尾规格](#片尾头像与个人-ip-落款)配套这句口播；用户不采用时，片尾卡与收尾口播都不加，成片在正片内容的结论处结束，写法见[口播稿写法](douyin-publishing.md#口播稿写法)。行动引导、商品卡、二维码及商业信息由本片目标和平台约定决定。常驻角标、声音标识和角色出现按已有选择采用。

## 片尾头像与个人 IP 落款

片尾卡由个人 IP 头像与「澄记 / 用计算机思维想现实」落款组成，与片尾口播「我是澄记，用计算机思维想现实。」配套出现，两者同时采用或同时省略。规格取自已发布团队影片的共同做法，以实际编码画面为准；主账号与 5W1H 账号共用同一规格。是否采用由用户逐片决定，问答与记录见[创作问答](intake.md#片尾头像与个人-ip-落款)。

### 采用与口播

- 每条新片按创作问答询问用户是否需要片尾卡；用户回答后记录在本片，后续制作与改片沿用该答案，不再重复询问。用户未回答前片尾保持待定，不默认加入或省略。
- 用户确认采用时，片尾口播使用「我是澄记，用计算机思维想现实。」，前一句从本片内容自然承接，写法见[口播稿写法](douyin-publishing.md#口播稿写法)。片尾卡、口播和对应字幕作为一组制作与验收。
- 用户不采用时，本片既不放片尾卡，也不念「我是澄记，用计算机思维想现实。」；成片在正片内容的结论处结束，最后一句落在本片内容上。

### 画面规格

| 项目 | 规格 | 主题映射与说明 |
|---|---|---|
| 头像素材 | 仓库 `assets/personal-ip/portrait.png`（512 × 512 透明扶正大头照，基础黑色连帽衫）；需要眨眼、呼吸与口型时，使用同目录 `rig.json` 与 `puppet.mjs` 的 `drawPersonalIP` 正面绘制，表情用 `happy` 或平静微笑 | 按仓库 `assets/personal-ip/README.md` 的“在影片中使用”复制到本片并登记来源与哈希；保持原有身份特征，不换装，除非用户为本片指定 |
| 画幅 | 竖屏 1080 × 1920 为基准 | 横屏按高度换算（系数 0.5625），落在横屏安全区内；横屏规格尚无已发布样例，首次采用时先出样片核对 |
| 背景 | 纯深色主题底：`palette.bg`；头像后方一处品牌黄柔光，`palette.accent` 透明度约 0.08–0.10、半径约 280–420px | minimal 为 #000000，kinetic 为 #05060A；正片其他画面、封面模板与装饰层不进入片尾卡 |
| 头像尺寸与位置 | 水平居中 x=540；显示边长约 400px（380–420），不超过源像素 512 | 片尾卡是身份声明的专用版式，头像居中放大到上述范围；其余镜头沿用[个人 IP 使用规则](styles.md#个人-ip-使用规则)的推荐尺寸 |
| 组合排版 | 自上而下：头像 → 名称「澄记」→ 标语「用计算机思维想现实」；整组围绕竖屏主视觉中心 y≈1000，头像顶约 y 610–730，标语下沿不低于约 y 1350 | 整组距字幕上沿至少 128px，避开贴底字幕；字幕以外的元素全部落在竖屏安全区 上220／下520／左72／右168 内 |
| 名称行 | 「澄记」，主题字体栈，字重 600–700，字号 64–120px；品牌黄标记在名称行上 | 两种已发布写法：名称用 `palette.text` 加名称下方居中短黄线（约 56 × 4px，圆角 2，透明度约 0.8，随名称展开），或名称直接用 `palette.accent` 着色。本片选定一种并记录 |
| 标语行 | 「用计算机思维想现实」，字号约 36–48px，字重 500–600，比名称小一级；可加 6–8px 字距 | 颜色用 `palette.text` 或 `palette.textSecondary`（minimal #86868B，kinetic #8B93B8），与名称保持清楚主次 |
| 账号署名 | 默认不显示。用户为本片要求时，在标语下方加一行「ONEINO.澄记」（与 `brand.json` 的 owner 一致），约 28px、字重 500、`palette.textSecondary`、透明度约 0.55 | 片尾卡不放二维码、网址、其他平台账号、联系方式与关注引导，合规见[合规清单](douyin-publishing.md#合规清单发布前逐条过) |
| 字体 | 主题字体栈：minimal 为 Inter + 中文字体栈，kinetic 为 Inter Tight + 中文字体栈；中文字形实际由中文字体渲染 | 编码后核对字形、字重与无乱码 |
| 字幕 | 片尾口播照常出贴底字幕，按小句拆为「我是澄记」「用计算机思维想现实」，位置沿用[竖屏版面默认](styles.md#竖屏-916-口播版面默认)；片尾卡不叠屏幕大字 | 章节导航等常驻层在片尾卡开始前淡出 |

颜色一律从本片固定主题读取。旧片曾直接写死琥珀色 #FFB340（当时的主题主色），对应今天的 `palette.accent`（#FFC712）；写死的 #F5F5F7、#000000 与 #86868B 分别对应 `palette.text`、`palette.bg` 与 `palette.textSecondary`。kinetic 使用同一结构与同一配色职责，取其自身 token；默认第二色 #5B3DF5 不进入片尾卡，保持单一品牌黄焦点。

### 时序与动作

| 项目 | 规格 |
|---|---|
| 位置与时长 | 全片最后一镜，在前一句与片尾口播之间的停顿中切入，比口播首字早约 0.4–0.6s；总时长按“提前量 + 实测口播时长 + 完整停留时长 + 可选淡出时长”计算。已有样例的 3.9–4.0s 仅作参考，本片按实际音频确定镜长与片末 |
| 进入 | 由上一镜硬切或约 0.4s 的上移交叉淡化进入。头像从开场起可见，或在约 0.6s 内缓出淡入并上浮约 30px；名称与标语在约 0.4–0.6s 内缓出淡入，带约 18–24px 上浮，minimal 可加由约 10px 到 0 的去模糊 |
| 与口播对齐 | 名称最迟在读到「澄记」时完整可读，标语最迟在读到「用计算机」时出现；两行也可在口播开始前一起出现。使用可动 IP 时，口型按片尾口播的音量包络驱动，口播结束后闭口 |
| 稳定停留 | 进场完成后固定镜头、头像、名称和标语坐标；身份阅读段保持稳定，眨眼和按真实口播驱动的口型可保留。需要角色表演时按本片内容单独设计动作 |
| 收尾 | 口播结束后整组完整停留约 1.5s，再结束于最后一帧；选择淡出时，在完整停留之后另加约 0.6s 将全画面淡至黑色并同步淡出剩余声音，该段计入总时长。本片选定方式并记录 |

例如提前量 0.5s、实测口播 3.0s、完整停留 1.5s，片尾总长为 5.0s；选择再淡出 0.6s 时，总长为 5.6s。先取得配音及词级时间，再确定片尾起止与全片时长，完整保留口播和落款读时。

### 实现与记录

本片按上述规格在 `src/` 中实现片尾卡，或复用已确认的本片实现；字体、颜色和动效参数从固定主题读取。采用记录写入 `evidence/events.md` 的“个人包装选用”表（目录编号 E099、E112），注明名称行写法、是否显示账号署名、收尾方式和口播实测时间；`brief.acceptance` 写入片尾卡与口播同步的验收目标。

## 每片选用与版本记录

1. **开工**：读取本片固定主题与用户选择，在 `NOTES.md` 写明本片沿用的识别规则、需要的组件组、与默认规则的差异及依据。已有视觉选择持续复用，剩余重要选择按[创作问答](intake.md)处理。
2. **分镜**：在 `evidence/events.md` 的“个人包装选用”表填写实际采用项：目录编号／组件组、表达任务、镜头、样式与变体、实现入口、验证状态。全部镜头继续按内容编排，组件状态与语义事件对齐。
3. **实现**：先核对本片已有组件与契约；可用画法沿用本片副本，新增画法写入本片 `src/`。同一组件的文字、素材与时长作为内容输入，字体、色彩、间距、边界与进退场从同一份样式读取。实现状态使用“待实现／已实现／样片通过／当前编码通过”，分别附源码或实际证据。
4. **验证**：为本片实际采用的画幅、明暗背景和内容长短选择代表性样例，包含最拥挤的一镜；在正常速度与 360px 宽下核对主体、字幕、人物条、来源和 IP 的关系。进入、停留和退出都保留连续观察证据。
5. **复用**：已确认方案记录其版本、样式参数、素材来源、适用条件和样片；跨片采用先核对共享层是否已有对应规范或组件。需要沉淀的通用实现通过[核心维护](maintenance.md)独立保存至权威位置，新片从核心初始化所需副本。核心与模板保持独立于 `projects/`。

旧片按自己的 `guide/`、固定运行时和已确认选择执行；新规则用于新片，已有影片的升级依用户指定范围实施。主题、源素材与成片证据分别保留版本身份。

## 审片验收

在 `brief.acceptance` 中加入本片可观察的包装要求，在 `evidence/review.md` 记录实际结果；采用 Production 的结构化审片时，将相应证据归入现有 captions、sync、quality 和 rights 检查。

| 检查 | 通过条件 |
|---|---|
| 身份与一致性 | 所有已采用组件的黄色职责、字体层级、笔画、容器和同类进退场一致；本片差异有选择依据，个人 IP 符合既有身份 |
| 内容与密度 | 每个元素有对应台词或画面任务；当前重点清楚，人物条、字幕、来源与主内容互相避让，段落构图随内容变化 |
| 语义与阅读 | 实测触发、强调和落定吻合讲解；短字幕、引文、单位与必要来源在目标画幅可读，最终结果有完整读时 |
| 证据与边界 | 原件、来源、画面性质和采用权利准确；封面素材用途独立；收尾、配音及身份使用符合执行角色约定；未采用片尾卡的成片不含收尾口播 |
